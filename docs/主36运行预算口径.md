主36项正式运行的预算均按 causal shift 后、实际参与 CE/KL loss 的有效预测位置计数。`runs36.csv` 逐项列出预测暴露、raw/padded 输入、库容量 K、实际唯一监督位置、重复暴露、b、λ、λ/b 及训练/教师计时；`grouped_summary.csv` 按方法×b 汇总三 seed 的均值、标准差和观察范围，`ratio_summary.csv` 只用于核对相同 b 的计数，不将不同方法混合成性能对照。

本36项全部完成10,000,000 target预测位置；target raw=10,019,570、padded=10,019,840。目标库唯一容量及实际唯一监督覆盖均为2,093,056，重复监督暴露为7,906,944。同一 b 在所有相关方法与 seed 间，下表计数完全一致；相同计数不表示不同 seed 的数据顺序相同。

K 是库的预测位置容量，不能替代本次实际唯一监督覆盖；例如 b=.01 尚未覆盖全库。上述唯一位置结论依赖本批数据已经验证无 exact duplicate chunks。λ=.05 与 b 分开记录，λ/b 分别为5、1、.5；B0 为未定义。训练实际分别按每步 target/replay 有效预测数归一化后，以 λ 加权 replay 均值。λ/b 是归一化系数的描述，不能当作测得的梯度贡献或新增 loss 权重。

raw 是每批 student 输入的 `attention_mask.sum()`，包括重复读取的上下文；padded 是 `input_ids.numel()`，还包含补齐位置。KL teacher 对同批输入的额外前向没有再次加进这两个计数，验证输入也不在这些训练流计数中。两者均不是 FLOPs、所有模型调用的 token 总量或实际硬件运算量。

冻结实现保留 partial chunk 的 offset：下次接着监督未消费位置，同时重新传入该 chunk 从起点开始的完整因果前缀。旧位置只作上下文，不重复计入该 epoch 的监督预算。CE/KL 使用相同的有效预测 mask；GPTNeoX causal attention 使位置 t 的 logit 不能读取 t+1 或其后的 token，loss mask 不替代因果 attention mask。因此保留完整前缀不会引入未来信息。

在本次512长度、全有效位置、micro16×accum4、306 optimizer steps 的条件下，独立 CPU 重算得 target student 前向1224批；三个非零 b 都是每步一批 replay，即306批，KL 还对应306批 teacher 前向。这些调用数列标为 derived，没有伪装成额外计时仪器记录。较小 b 减少监督预测数，但上下文重读、padding、调用及固定 target/optimizer/验证开销仍存在，所以不保证总墙钟按 b 同比例下降。B4三 seed 的观察训练时间范围为 b=.01：193.31–198.04秒，b=.05：195.90–201.70秒，b=.10：202.21–203.66秒；其他方法及完整时间类别均保留在 CSV。这只是当前硬件、精度、batch/序列和并发环境下的观察，不是 b 对运行时间的独立因果效应估计，也不推广到其他形状或模型。

`training_teacher_forward_seconds` 已包含在 `training_seconds`；validation teacher/KL arithmetic 子项已包含在 `validation_seconds`，不能再相加。表中另外保留 setup、checkpoint、总墙钟及四项主要计时之和的残差。冻结代码在相邻时刻分别采样 elapsed 与总墙钟，微小采样差单列，不当作新的成本。
