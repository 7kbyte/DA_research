# 已交付权重的按需恢复示例

下面恢复两个已持久发布的 **410M final**：主实验 B4/seed11（b=.05、λ=.05）和补充 A 验证选定 B4/seed11（b=.05、λ=5）。两者均实际训练到 10M target / 0.5M replay 预测 token。只提取指定成员，无需展开整个 TAR；需要可运行现有 CPU codec 的 Python、torch、numpy、safetensors 环境。

先在一个新的目录提取共用基座、工具和主 manifest。A 是增量包，**不自包含基座**；此处基座来自已持久 primary 包，不依赖历史 `/tmp` 模型路径或重新下载。 primary 内附 decoder 与 A 内附 decoder 逐字节相同，代码 SHA `3c2bcf9e38773ae4f69c27f85f342356dbefcb53d817be4321da6e9c4e550e1a` 也正是此 A ZIP 记录的 encoder 源码 SHA；直接核对归档源码可见它会写入下文的来源类型与完整 fingerprint，A 的额外 metadata 字段兼容。

```bash
PRIMARY_TAR=/data/202610/7kb/research_delivery/primary_final_weights_lossless_v1.tar
A_TAR=/data/202610/7kb/research_delivery/supplement_A_selected_final_weights_lossless_v1.tar
RESTORE_DIR=$(mktemp -d /tmp/replay-restore.XXXXXX)
cd "$RESTORE_DIR"
export CUDA_VISIBLE_DEVICES=''
export OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2

tar --extract --file="$PRIMARY_TAR" --keep-old-files \
  primary_final_weights_manifest.json \
  base/pythia-410m-final/model.safetensors \
  base/pythia-410m-final/config.json \
  base/pythia-410m-final/tokenizer.json \
  base/pythia-410m-final/tokenizer_config.json \
  base/pythia-410m-final/special_tokens_map.json \
  base/pythia-410m-final/README.md \
  tools/src/replay_study/weight_archive.py \
  tools/src/replay_study/__init__.py \
  tools/scripts/archive_model_weights.py
```

主 B4 的 ZIP 和该条件自己的 metadata 分别位于 `weights/...xor.zip` 与主 manifest 的同名 `logical_runs` 条目。提取一份 ZIP 并恢复到新文件：

```bash
tar --extract --file="$PRIMARY_TAR" --keep-old-files \
  weights/formal_deterministic_B4_s11_b0p05_w0p05.xor.zip
python tools/scripts/archive_model_weights.py --threads 2 decode \
  --archive weights/formal_deterministic_B4_s11_b0p05_w0p05.xor.zip \
  --base base/pythia-410m-final/model.safetensors \
  --output restored/main_B4_seed11_final.pt
```

A B4 λ5 的 ZIP 是新模型权重，自己的完整非权重/非 optimizer metadata 另有 sidecar；此例不是 B1 那种引用 primary 权重的别名。继续在同一目录运行：

```bash
tar --extract --file="$A_TAR" --keep-old-files \
  supplement_A_selected_final_manifest.json \
  metadata/lambda_sweep_deterministic_B4_s11_b0p05_w5__validation_selected_lambda_final.source_metadata.pt \
  weights/lambda_sweep_deterministic_B4_s11_b0p05_w5__validation_selected_lambda_final.xor.zip
python tools/scripts/archive_model_weights.py --threads 2 decode \
  --archive weights/lambda_sweep_deterministic_B4_s11_b0p05_w5__validation_selected_lambda_final.xor.zip \
  --base base/pythia-410m-final/model.safetensors \
  --output restored/A_B4_lambda5_seed11_final.pt
```

`--threads` 在 `decode` 前。decode 自动核 base 文件 SHA、每个基底 FP32 tensor SHA、恢复 raw tensor SHA 和完整模型 fingerprint；已有输出会被拒绝覆盖。两个模型的预期 `sha256_model_state` 分别是：

| 模型 | 完整模型 fingerprint SHA256 |
|---|---|
| 主 B4 seed11 | `63069435cb5ea77931a58d7b00b573bcc4b517fdea283f7b551345997508c28c` |
| A B4 λ5 seed11 | `ffc55075d0e8c14e77548752bd0de648858f75eeef98b8bffef88b160cb1c374` |

两者的 `state_elements` 都是 `405334016`。这个 fingerprint 标识权重位型，不是恢复 `.pt` 或原始完整 checkpoint 的整文件 SHA。

查看完整 fingerprint、恢复类型、来源类型，以及两项自己的 metadata：

```python
import json
from pathlib import Path
import torch

for name in ("main_B4_seed11_final", "A_B4_lambda5_seed11_final"):
    saved = torch.load(f"restored/{name}.pt", map_location="cpu",
                       mmap=True, weights_only=False)
    provenance = saved["lossless_delivery_provenance"]
    print(name, json.dumps({
        "model_fingerprint": provenance["model_fingerprint"],
        "checkpoint_kind": saved["checkpoint_kind"],
        "source_checkpoint_kind": provenance["source_checkpoint_kind"],
        "source_checkpoint_sha256": provenance["source_checkpoint_sha256"],
    }, indent=2))

main = json.loads(Path("primary_final_weights_manifest.json").read_text())
main_row = next(r for r in main["logical_runs"]
                if r["condition_run_id"] == "formal_deterministic_B4_s11_b0p05_w0p05")
print("Main own metadata:", main_row["original_checkpoint_metadata"])
sidecar = torch.load(
    "metadata/lambda_sweep_deterministic_B4_s11_b0p05_w5__validation_selected_lambda_final.source_metadata.pt",
    map_location="cpu", weights_only=False)
print("A own logical identity:", sidecar["logical_identity"])
print("A original explicit checkpoint_kind:",
      sidecar["original_checkpoint_metadata"].get("checkpoint_kind", "<not explicitly stored>"))
```

恢复文件的 `checkpoint_kind` 均为 `model_only_lossless_xor_restored`。主 B4 属兼容的早期 v1 ZIP，未记录可选 origin-kind 字段，故其 `source_checkpoint_kind` 显示 `unspecified_in_legacy_v1_archive`；final 身份由 manifest 固定条件及实际曝光确认。A 的来源类型显示 `full_training_checkpoint`，但原始 latest 本身未显式设置 `checkpoint_kind`，其来源类型是编码器依据 optimizer 存在记录的 fallback；sidecar 保留原字段是否存在，不能把它和 A 的 `validation_selected_lambda_final` 逻辑身份混为一谈。两包均不含 optimizer，不用于完整 Adam 续训。

基座文件 SHA256 为 `3e09001631bb18ec8a6f4522f8e6ab26a53099e69228f9822adc91bfbe27511b`，pinned revision 为 `9879c9b5f8bea9051dcb0e68dff21493d67e9d4f`。primary TAR 身份 SHA 为 `2bb090fbe7df172b31102068715143ab702087ff49f77ef7dfd5db3637c928b1`，A TAR 为 `0dfec20b1bf9dde38b0d0d453c821eb088490bde188dc0e19bc498cc37b04631`；发布证据分别见 [primary receipt](primary_weights_durable_publication.json) 与 [A receipt](A_selected_weights_durable_publication.json)。

本文只读取 TAR headers、小 manifest、ZIP metadata 和工具源码，已核所列成员均为安全相对路径的普通文件、CLI 参数正确；没有新解压或执行模型恢复，也没有重新扫描整 TAR。两例的实际全 tensor uint8 往返验收已经由各自 manifest 的 `bytewise_verification` 记录完成；主 B4 为 292 tensors，A B4 也为 292 tensors。详见 [成员核对收据](已交付权重恢复示例_成员核对.json) 与 [底层格式说明](无损权重交付格式.md)。C 尚未完整发布，不在本示例范围。
