# 结果分析与统计协议

原RQ1来源对照也按相同seed、b、λ配对报告：B3−B1（生成CE−C4 CE）和B4−B2（生成KL−C4 KL），与M−B4、C−B4、B2−B1、B4−B3一并保留。B0的b=λ=0，不静默套用同b/λ规则；当前未增加相对B0的额外配对。补充A保持独立phase，选参规则另见[补充A验证选参与分析](补充A验证选参与分析.md)。

本协议的实现为 `src/replay_study/analysis.py` 和 `scripts/analyze_results.py`。分析只读取 JSON，不加载模型或 CUDA。正式运行列表由 `docs/protocol_status.json` 的 active_registry 指针确定，拒绝混入 pilot；旧的 `configs/formal_registry.json` 只作 provisional 数值诊断。旧初始验证文件 `results/pilots/v3_lr/initial.json` 是未适应教师的完整评估，而非训练后 pilot 端点；新协议的验证基线必须显式指定，避免无意沿用旧数值后端的基线。

当前正式比较使用独立strict namespace `configs/formal_deterministic_registry.json`，基线为 `results/pilots/lr_deterministic_v3/initial_cudnn_matched.json`，具体授权仍以[状态入口](protocol_status.json)为准。CLI必须显式传 `--registry` 和 `--analysis-status active`，核对全部科学配置、实际执行政策及完整曝光，拒绝provisional/superseded/invalid项，不能从目录glob其他批次补数；未完整时只能明确partial。

历史记录：2026-11-06 04:18 UTC原批次因数值一致性问题降为provisional，其注册表与原始证据仍保留。CLI默认分析状态仍为 `provisional-numerical-noise`，用于防止无意将历史输出升格成科学比较；该默认值不表示当前strict批次仍未通过数值资格审查。旧批次的图和manifest抑制方法效应比较，不能补入当前正式端点。测试JSON入口也只允许显式active状态。

CLI 默认读取 `docs/protocol_status.json` 并归档快照：active_registry 为空、与显式注册表不一致或同时列入 provisional 时均拒绝 active 分析。连尚未形成 summary 的实时验证事件也要验证 start/resume 中的运行名和科学配置，不能把旧目录的轨迹接到新批次。Python API 的 analysis_status 同样必须显式传入；生产分析应同时传 protocol_status_path。

生产 active CLI 还要求初始验证及初始端点都有 execution_provenance：比较 Torch/CUDA 版本、BF16/FP32、SDPA 允许集合（含 cudnn_sdp）、strict/warn_only、TF32、cuDNN 确定性/benchmark、CUBLAS workspace 和模型权重 dtype。训练内验证从实际运行 provenance 映射核对，未来测试 JSON 与其初始模型核对；只相同的 precision 字符串不足以证明评估数值政策相同。

## 指标方向与完整性

对每个固定 seed，定义目标学习收益

\[
G_{new}=L_{target}(\theta_0)-L_{target}(\theta),
\]

越大表示目标域 NLL 降低越多。分别定义 C4 与 WikiText-103 的遗忘

\[
F_{old,j}=L_j(\theta)-L_j(\theta_0),
\]

越小越好；负值表示该评估语料的 NLL 改善，不强制截为零。KL 是全词表 `teacher || student`，越小表示所选上下文上的输出分布越接近初始教师，不等同于所有能力保留。不同语料分别报告，不通过将语料 token 混池形成一个“总体遗忘”。NLL 单位为 nats/预测 token。

默认使用训练结束时固定目标曝光的验证端点，不以最低验证 NLL checkpoint 替代。只有 status=completed、实际目标曝光等于冻结配置预算、末次验证恰好位于该曝光、语料 complete_corpus=true、模型 revision 与初始基线匹配的运行才进入端点统计。注册表、配置、摘要、初始结果的 SHA256 写入 manifest。部分结果可生成，但须显式 `--allow-partial`，manifest 与图标题标为 PARTIAL，并记录每个组合的 n/expected_n；缺失 seed 的 SD 不填成零，也不以早完成子集作最终排名。

## seed 层面的描述与配对差值

每个 group/b/λ 输出每 seed 原始指标、均值、样本标准差（ddof=1）和 n。SD 描述训练 seed 的离散程度，不是标准误或置信区间。n<2 时 SD 未定义，CSV 留空，图中不画误差棒。主 scatter 分 C4 与 WikiText 展示 Gnew 对 Fold：小点为 seed，大点及横纵误差棒为均值 ± SD。主比较使用 b=.05，B0 为 b=0；B4/M 的 .01/.05/.10 预算曲线另画，不能把 b 的变化解释成 λ 的变化。

预定配对比较为 M−B4、C−B4、B2−B1、B4−B3、B3−B1、B4−B2，必须匹配 seed、b 和 λ。后两项分别在CE和KL内部比较生成/C4来源，是原RQ1对照，并非根据结果新增有利差异。先在每 seed 内相减，再对差值求均值与 SD；不得把两个独立组 SD 的组合当成实际配对变异。Gnew 差值为正支持前一个方法，Fold/KL 差值为负支持前一个方法。没有匹配项的 seed 不参与该对，期望配对数仍保留。全部预定比较一并报告，不依据显著性挑选。这里不把三个 seed 的描述性统计包装为强确认性检验。

另设 `identical_bank_controls.csv`：当D与B4的实际tensor SHA相同时，D−B4只作为同数据、同seed的数值一致性对照，不解释为去重效果。历史非strict批次在04:16 UTC的seed11出现首步前向CE/KL相同、梯度范数分叉及最终目标验证NLL约0.0129的差异，原始[证据](../artifacts/assets/identical_bank_training_variability.json)保留；该批次已隔离，不用其噪声尺度替代当前strict不确定性。未认证具体旧CUDA kernel是根因，也不再把这个待查解释写成当前实验尚未解决的状态。

当前strict批次的seed11/22/33同库空对照均已完成完整10M训练，记录的训练量和全部验证NLL/KL最大绝对差均为0，[最终运行审计D_B4_null_controls](../results/formal_run_audit.json)逐seed列证据。最终审计model_weights_compared=true，三个seed各自的最终405,334,016元素模型状态SHA也分别逐位一致；seed11最早的[完整资格审计](../results/formal_deterministic_qualification.json)另行保留。此结果支持当前冻结执行路径下的数值可比性；因候选池无整块重复、D没有改变库，不能解释为“去重提升或没有提升保留”的有效干预实验，也不保证换后端后继续确定。

## 未来冻结测试 JSON 接口

当前默认运行不会读取测试模型结果。只有显式传入 `--evaluation-root ROOT` 才读取 `ROOT/initial_pythia-410m.json` 和 `ROOT/<run_id>/{final,best}.json`，格式沿用评估脚本的 `corpora/chunks`。必须另指定输出目录，防止覆盖验证分析。final 必须对应摘要的最终 checkpoint；best 必须对应仅由验证选择并记录的最佳 checkpoint。模型 revision、精度、完整语料 token 数及 checkpoint 路径均核对。最终与最佳模型是分开的预定结果，不根据测试结果再选择哪一个。

best 的 step 和目标/回放曝光由 best_target_validation 与验证轨迹精确匹配取得，不能用最终 10M counters 填充早期模型。端点表的 target_prediction_tokens/replay_prediction_tokens 表示被评估模型的实际曝光，full_training_* 表示完整运行支出；训练成本仍计整个运行，不能因选择早期模型而抹去后续实际支出。best 端点若曝光不同，不作“相同检查点训练预算”的表述。

验证侧另提供 `scripts/analyze_validation_best.py`，只从完整、已核对的正式摘要中提取best匹配轨迹点，不读取测试JSON。它独立输出best验证表及实际曝光；因目标验证数据也用于选择best，明确存在选择乐观性，不作为独立测试或替代final固定10M主端点。补充A选λ仍只使用final，禁止读取该best表选λ。

每个 chunk 必须有 doc_id、chunk_index、有效预测 token 数、NLL 和；KL 统计需要 KL 和。先把一篇文档所有块聚合。两模型的文档集合、块身份和 token 数必须完全一致；不同集合直接报错，不静默取交集。按 token 加权的 NLL 为损失总和除有效 token 总数，等文档 NLL 为每文档 NLL 的算术平均，二者是不同估计对象，均报告。

paired document bootstrap 每次有放回抽取 D 个文档 ID，并在两个模型中使用同一组抽样 ID；一篇文档的全部块始终共同进入。每次重新计算 token 加权的比率和等文档平均，使用固定 RNG seed、默认 5000 次抽样和 95% percentile CI。先算 A−B，再对配对文档抽样；目标收益对 NLL 差取反，并同时反转 CI 两端。不会逐块 bootstrap，也不把 bootstrap 重复数视为实验 n。区间明确标注 **conditional on the trained checkpoints**，不包含重新训练、重新生成/选库、调参或重新划分数据的变异，不能替代训练 seeds 的 SD；不同 seeds 的 bootstrap 结果分开输出。

这些区间还受文档非概率抽样与语义相关性限制，不保证覆盖完整 FineMath/C4 总体的未知参数。

## 相近目标验证损失的补充诊断

只用验证轨迹，为两运行加入同一未适应模型的零曝光锚点，在双方达到的改进范围内取五个均匀内部 loss 水平。共同范围下界为双方最小验证 NLL 的较大者，上界为初始目标验证 NLL；没有共同改进范围就不输出点。按时间找到每个水平的**首次下降穿越**，用实际相邻验证检查点间的分段线性插值描述旧域指标与曝光，同时保存两端 step/曝光/NLL、插值比例和穿越次数。非单调轨迹明确标注，不改选后续可能更有利的穿越分支。

该表为 piecewise-linear validation diagnostic：绝不外推，不构造或声称真实中间模型，不把插值曝光当作实际计算成本，不把相近目标 loss 说成等训练预算，也不把五个相关插值点算作额外 seeds。它用于检查“保留较好是否只是目标学得较少”的可能解释，不是测试集检查点选择规则。provisional 数值噪声批次不生成这一科学比较。输出分别为 matched_validation_ranges.csv 与 matched_validation_loss.csv。

## 成本口径

训练成本父项为 setup、training、validation、checkpoint I/O。训练教师前向已包含在 training，验证教师前向和 KL 算术已包含在 validation，子计时以 nested 列展示且禁止再次加总。父项之和与 total accounted wall 的差值单列，保留 I/O/调度等未分类开销；完整实际资源成本仍应结合外部进程 wall 与恢复日志，因为回滚失败工作和最后一次恢复 checkpoint 写盘可能没有计入持久化 counters。

`training_costs.csv` 与成本均值图只比较达到冻结预算的完整运行；`observed_run_costs.csv` 另外保留本注册表内所有已有摘要的运行，包括 interrupted/max_steps/deadline 的实际支出和曝光。未完成模型不进入端点比较，但不能在项目资源账本中抹去其成本。该表不含其他注册表或 pilot 的支出，也不能单独冒充整个研究的全部实际消耗。

共享准备另表按每 seed 计一次生成、联合教师 NLL/最后层特征提取、各选库操作；聚类计时是 cluster selection 的嵌套诊断。共同池用于多种方法、多个 b，不将同一真实生成费用反复加入本次实验总成本。方法独立部署的反事实准备成本与本次实验实际共享成本需要清楚区分。pilot 准备费不混进正式表。

[独立统计成本诊断](选择统计独立成本诊断.md)表明本设置的C head-free特征提取可比M NLL-only更快；不能凭“聚类”名称断言总体更贵。该诊断计时不回填或重加为历史joint实际共享成本，详见[局部解释与实测成本边界](局部Fisher解释与选库诊断.md)。

## 执行示例

```bash
# 当前strict：只读验证，未齐备时允许明确标为partial。
python scripts/analyze_results.py --registry configs/formal_deterministic_registry.json \
  --baseline results/pilots/lr_deterministic_v3/initial_cudnn_matched.json \
  --analysis-status active --allow-partial \
  --output results/analysis/formal_deterministic_validation_partial

# 全部正式验证端点齐备后，不带 --allow-partial；不齐备直接拒绝最终输出。
python scripts/analyze_results.py --registry configs/formal_deterministic_registry.json \
  --baseline results/pilots/lr_deterministic_v3/initial_cudnn_matched.json \
  --analysis-status active --output results/analysis/formal_deterministic_validation

# 完整后可另导出验证选出的best及实际曝光；不替代上面的final主比较。
python scripts/analyze_validation_best.py --registry configs/formal_deterministic_registry.json \
  --baseline results/pilots/lr_deterministic_v3/initial_cudnn_matched.json \
  --output results/analysis/formal_deterministic_validation_best

# 未来测试冻结后显式启用；不是当前任务要执行的命令。
python scripts/analyze_results.py --registry /path/to/active_registry.json \
  --baseline /path/to/active_initial_validation.json \
  --analysis-status active --evaluation-root results/evaluations \
  --checkpoint final --output results/analysis/test_final
```

每幅图同时导出 PNG（320 dpi）、PDF、SVG，英文标签和中文说明共存。图中同一组多个 seed 是训练重复；v3 与 extended 评估共享来源和部分文档，不能通过另画一套图宣称获得新的独立测试。
