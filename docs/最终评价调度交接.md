原supplemental master的训练截止为2026-11-07 00:00 UTC，默认23:50停止活跃任务并收尾；硬截止03:26:32 UTC。当前311个job定义与旧state保持原样。仅在旧master及其所有child/process group完全退出后，才能使用独立scripts/handoff_evaluation.py构造并启动评价队列。本文及示例均不构成已启动第二scheduler的记录。

配置schema示例见configs/final_evaluation_handoff_spec_example.json。它设置example_only=true，会被prepare拒绝，且仅列主评价以说明接口。最终操作spec必须另存新文件，显式列出全部拟执行的冻结评价queue SHA与v2 manifest SHA；prior_sources列所需原始baseline/canonical评价来源。所有评价输入、checkpoint、代码的SHA仍由冻结manifest绑定。不得将含训练任务的原311队列作为evaluation_sources或prior_sources；旧队列只用于核对历史定义和保存快照。

```bash
python scripts/handoff_evaluation.py prepare \
  --spec configs/final_evaluation_handoff_spec.json \
  --spec-sha256 EXPLICIT_REVIEWED_SPEC_SHA256 \
  --output-dir logs/final_evaluation_handoff_v1
```

prepare先取得旧state对应.lock，再核验旧scheduler PID不存在、全部已记录child PID/process group不存在，连未reap的进程也拒绝。之后仅合并明确列出的run_frozen_evaluation.py job及其完整依赖闭包，必须包含原始initial baseline；同ID定义必须完全相同。外层argv只能是冻结worker、显式manifest/SHA/job-id、cuda:0；内部scorer只能是冻结run_evaluate.py或evaluate_tasks.py，不允许训练入口、shell、嵌套scheduler、设备环境覆盖或verify-only伪任务。

新目录保存独立queue.json、state.json、handoff.json及旧state/queue逐字节快照。只继承旧state中completed、returncode=0、定义相同且完整输出/执行凭证SHA全部通过的相关job；无关训练记录不进入新state。凭证由冻结worker在完整split/policy验证后写出；交接仅解析manifest与_execution.json，模型分数和预测只流式计算SHA，不做JSON解读。输出缺失、损坏或凭证不完整则恢复pending，原始失败/耗时记录保留在旧快照。有效的完整baseline直接继承，不再运行。跨manifest reuse必须核验新logical alias自身的零额外推理凭证，不能把旧canonical的凭证误当作新job完成。

```bash
python scripts/handoff_evaluation.py start \
  --handoff logs/final_evaluation_handoff_v1/handoff.json \
  --handoff-sha256 EXPLICIT_REVIEWED_HANDOFF_SHA256
```

start再次核验旧master退出、所有快照/新state/源SHA及继承输出，拒绝重复launch。它使用短Popen(start_new_session=True)启动独立4GPU scheduler并立即返回，日志与state留在新目录。新scheduler继承并持有旧master的锁，正常运行期间旧master无法重新取得锁。除新评价scheduler外不再启动其他GPU scheduler；若调度器崩溃，需先核查新state中所有存活child，再使用新的交接命名空间，不能直接重启旧训练队列。
