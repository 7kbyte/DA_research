# 补充 B/C 的验证分析边界

运行入口为 `scripts/watch_auxiliary_validation.py --watch`，现行协议为 `docs/auxiliary_validation_analysis_protocol_v2.json`。v1 为首次 prepared-only 门禁的历史记录；v2 在任何 B/C 适应后验证读取之前增加了逐 job 的冻结命令、调度器 definition SHA、成功退出码及登记输出存在性检查。两个版本都不授权测试 NLL 或行为分数读取，不会启动 GPU 推理、改变训练/选参或重写主 active 状态。

每个 cohort 必须先完整，才读取其适应后验证端点：B 为60项；C 为410M的24项、1B的24项、2.8B的15项，四个 cohort 独立触发。410M/1B 另外等待训练方独立审计的 completion 收据，验证 audit、final/best 模型等价证明和源输入 SHA。2.8B 无 D 对照，完整15项后调用只读训练审计器核查预算、验证轨迹和选点。数值同库控制不相等不等同于源文件审计失败，但必须明确报告；仅存在完整权重等价证据时可声称权重相同。本分析始终保留逐运行结果，不新增推理 alias。

B 使用原 `artifacts/bank_variance_410m_v1/registry.json` 的科学身份，额外绑定 activated runtime registry 与 activation。准备和实际配置只允许已记录的 deadline 覆盖，其余科学字段、bank manifest、张量内容、selection seed 与完整方法×K×draw矩阵均须一致。继续调用既有 `analyze_bank_variance` 统计核心，不将补充 phase 伪装为 primary。B 的重复单位是 selection_seed1001–1010；generation pool 和训练 shuffle 都固定为11。这估计给定生成池和训练顺序的选库条件变异，不估计十个训练 seed 或多个生成池的不确定性。方法之间同 draw 标签的配对差先相减再求均值和样本 SD，但不保证各选择算法内部随机数完全相同。

C 各自绑定 frozen extended protocol、输入 snapshot、正式 registry、对应初始验证基线及实际执行策略。正式组来自冻结的完整矩阵（410M/1B各8组，2.8B为5组）；原 protocol 的 `groups` 字段记录的是 λ 校准组，不能用于删减正式方法。C 只在同一模型内部作三训练 seed 配对，缺少方法的预定对照显式标为未登记。扩展训练包含主训练前缀，扩展评估与主评估共享 hash 分区且不独立；不同模型、horizon、数据不构成因果尺度对照。

所有结果只用验证记录。G=初始数学 NLL−当前数学 NLL；F=当前旧域 NLL−初始旧域 NLL。final 使用冻结固定目标曝光；best 为目标验证轨迹第一个最低点，报告其真实 target/replay token 数，不能把它标成完整训练曝光或视为等预算。误差条为声明重复单位之间的样本 SD（ddof=1），不是 SEM，也不是文档 bootstrap CI。验证记录缺少逐 chunk 贡献时不补造等文档指标。

成本表每个实际训练运行只出现一次，final/best 共用这份完整训练成本；teacher forward 等子计时不重复加到父计时。B 的共享生成/特征准备费也不乘以60。输出包括端点、成对差、逐步验证轨迹、来源 SHA、实际执行策略、中文说明和精确7英寸 PNG/PDF/SVG 图。完整 manifest 最后发布；进度入口为 `logs/auxiliary_validation_analysis_watch.json`。A 的验证选 λ 与完整分析由训练方 watcher 负责，本入口不重复执行。
