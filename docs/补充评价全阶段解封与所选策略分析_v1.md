# 补充评价全阶段解封与所选策略分析 v1

本协议只增加 CPU 分析门禁和独立补充表，不修改冻结评分器、wrapper、训练、验证选参规则或主统计定义。准备阶段不读取任何补充 heldout NLL 或行为分数，不加载模型，不启动 GPU。真实解封须等待 root 对准确 plan SHA 的显式授权。

机器协议已冻结为 `docs/supplemental_aux_analysis_protocol_v1.json`，SHA256 `42223bbb594a57055699a7906e8ab634c29e1c268007062426c3b771a6e56f9f`；9份命令模板为 `configs/supplemental_aux_analysis_commands_v1.json`，SHA256 `f9da47a4efd3e3555e1293d47262a2d791abf5692690107b3f4d8984dec15433`。绑定v5 catalog `90163f7a77529434c872f52f41d45151bf09826ddd17ab58ea48d21d16f3d186` 与正式 CPU preparation receipt `b1e8d66ad0ed8074064cf5c587725d4da2314869e95237e2c354d91e4268bcc9`。这些是准备来源证明，均不等于读取真实分数的授权。

## 解封顺序

独立入口为 `scripts/analyze_supplemental_phase.py`。它不调用调度器，也没有 `allow-partial` 选项。

1. `initialize-protocol` 绑定已经冻结的 preparation catalog、9个科学合同、原始 registry/protocol/data 身份、评分源码 SHA、已有 prior manifest/queue 和分析源码 SHA。v5 外围 CPU hash cache 不改变本分析的来源完整性要求；使用训练代理正式发布的 v5 catalog/ready-root，不推测未发布路径或提前制造 READY。
2. `prepare` 要求真实完整 READY，绑定 READY/spec/queue/manifest SHA、全部逻辑条件、物理作业及精确 prior 闭包。A 同时绑定完整验证选择文件 SHA、126格来源与18个真实所选 ID；不会重新计算或替换 λ。尚无合法 READY 时只保留命令模板，不生成假计划。
3. `check` 只做结构、状态、全字节 SHA 和 attestation 核验。先要求整个闭包定义 SHA 正确、completed/rc0、无 missing outputs，然后才访问结果字节。随后验证所有实际 checkpoint、公共及逐端点输入、imported baseline、canonical inference、reuse 和 logical alias、完整 summary/任务 JSONL 输出集合的 SHA。此步骤不解析 score JSON/JSONL；无真实分数写入检查回执。
4. root 独立审查并创建授权文件。必须包含 `authorized_by: root`、`allow_score_analysis: true`、准确 plan/protocol/READY/manifest proof、contract ID、完整 expected_counts、`allow_partial: false`、科学条件已冻结及“不用 test/behavior 选参”的声明。`prepare` 自动产生的 `_root_authority_TEMPLATE.json` 始终为 **false**，不能直接当授权。
5. `analyze` 重新验证授权和整个完整性门禁，先 fsync 保存 whole-phase readiness，再以 first-writer-wins 写入按 **contract ID + manifest SHA 固定路径** 的首次语义解封回执，最后才调用既有 collector。换输出目录或重跑不能重置首次时间。回执记录“紧邻调用 collector 前”，不声称它就是首次 JSON 字节解析的微秒时间。若 collector 后续失败，保留真实首次回执，不覆盖、不伪装从未解封；恢复需 root 另行审查。

canonical/prior closure 只包含本阶段确实依赖的 baseline/forward/materialization，不要求读取无关 prior 阶段的预测。模型状态等价只接受真实完整 state fingerprint、双方 checkpoint SHA、算法/source proof；false comparison 不产生 alias。C 两端点即使分目录统计，解封仍须 final/best 一起过门禁。

## A：完整λ曲线与验证所选策略比较

全126个 NLL 端点保留原 collector 的42个 λ×method 格，以及固定同λ的原有配对和统计。新增18点表通过验证选择中的 `condition_ids` 精确连接；同时保留 method、各自 λ、b、training_seed、actual_run_id、checkpoint SHA、真实 target/replay exposure 和完整训练 committed-path 成本身份。18点是已有126点的视图，**增加0次 GPU forward，不进行新选模**。

六个独立比较固定为 M−B4、C−B4、B2−B1、B4−B3、B3−B1、B4−B2。每边使用该方法已经完成的验证选择 λ，即“各自验证选λ后的策略比较”；method 与所选 λ 一起变化，不能解释成固定同λ下 objective 的因果效应，也不能筛到一个共同 λ 后丢失所选 ID。逐seed先相减，再给三seed个体、均值与样本 SD (ddof=1)。这组三seed也参与了共享λ的验证选择，因此所选表的SD描述这些checkpoint在该选择条件下的离散度，不估计重新运行整个选参流程的不确定性。固定同λ的原有表继续独立保留。

NLL 的文档 bootstrap 沿用现有同文档、同chunk/token身份配对实现，5000次、seed20261106。原始区间符号为左减右 NLL/KL；目标增益 G_new 左减右须反转目标 NLL 差的符号，输出明确标注，不混用。重采样单位是一整篇文档及其全部chunks，不把chunks当独立文档，也不把bootstrap draws当训练重复。

行为评价保留 acc_norm 主展示、acc 辅助，分别报告 initial→adapted 的 CC/CW/WC/WW、条件遗忘/习得；新增策略对比在相同 task/item/fingerprint/gold 上配对，以“右策略→左策略”命名转移计数，避免把它称为 initial-teacher 遗忘。两套score各用自己的预测和计数；配对 draw stream 由固定总seed、左右方法、训练seed、任务、score确定，重复执行可复现。

Wilson 与 paired-example bootstrap 依赖题目独立或可交换的抽样假设。HellaSwag 等可能存在同源活动、上下文关联；这些区间只能作为条件于实际训练 checkpoint 的题目描述，不能自动称为目标总体或训练随机性的置信区间。文档 bootstrap 也依赖文档独立/可交换假设，相关来源没有自动获得校正。主表始终保留三训练seed个体和样本SD，不能用成千题目或bootstrap draws增大训练重复数。

新增λ曲线尺寸为7×6.6in，包含全部126个checkpoint的seed点及mean±sampleSD，配套 CSV、PNG/PDF/SVG。条件bootstrap另表，不把条件区间绘成跨seed置信区间。best真实选点曝光和full-training总成本分开；不能按best曝光比例缩放整次训练费用。

## B、C及行为命令模板

`prepare-commands` 为上述全部9份合同输出结构化 argv，不执行它们。`<READY_SHA256>`、`<PLAN_SHA256>`、`<ROOT_AUTHORITY_SHA256>` 必须在对应真实文件产生后替换；未完成训练不得填造摘要/checkpoint。示例：

```bash
python scripts/analyze_supplemental_phase.py prepare \
  --ready artifacts/evaluation_ready_v5/supplement_B_nll/READY.json \
  --ready-sha256 '<READY_SHA256>' \
  --protocol docs/supplemental_aux_analysis_protocol_v1.json \
  --protocol-sha256 '<PROTOCOL_SHA256>' \
  --contract-id supplement_B_nll \
  --output artifacts/analysis_prepared_v1/supplement_B_nll.json

python scripts/analyze_supplemental_phase.py check \
  --plan artifacts/analysis_prepared_v1/supplement_B_nll.json \
  --plan-sha256 '<PLAN_SHA256>' \
  --state '<STATE_WITH_COMPLETE_PRIOR_AND_NEW_CLOSURE>' \
  --output results/supplemental_analysis_v1/supplement_B_nll_readiness.json

# 只有root独立授权后可运行；本准备任务不会运行下面的命令。
python scripts/analyze_supplemental_phase.py analyze \
  --plan artifacts/analysis_prepared_v1/supplement_B_nll.json \
  --plan-sha256 '<PLAN_SHA256>' \
  --authority '<ROOT_AUTHORITY_JSON>' \
  --authority-sha256 '<ROOT_AUTHORITY_SHA256>' \
  --state '<STATE_WITH_COMPLETE_PRIOR_AND_NEW_CLOSURE>' \
  --output results/supplemental_analysis_v1/supplement_B_nll
```

C 对应替换 contract ID 和路径即可，NLL 会在一次完整phase gate后分别输出final/best。补充行为用 `*_behavior` 合同，A先等待完整验证选择18ID，其余C按完整各模型final，B不做行为。原分析source被修改、READY变化、源checkpoint变动、缺baseline/alias/source attestation，或授权文件不精确匹配时均拒绝。

## 成本与准备状态

本工具的 `score_blind_verification_wall_seconds` 是 CPU/I/O 全字节核验wall，可能包括很大的 checkpoint 与来源 hash；不是GPU时长，不能再加进已包含核验的调度whole-slot中。collector/统计/出图、proof门禁、报告、持久化均需要真实尾部时间，未测项不写0。已有预算v3保持独立冻结，准备工具不会据测试或行为分数更改训练、后续条件或GPU预算。

测试只使用临时合成 fixtures，包括无效JSON“私有结果”以证明门禁只hash不解析，以及独立合成合法结果的完整collector集成。真实补充和行为分数在本准备阶段始终封存。
