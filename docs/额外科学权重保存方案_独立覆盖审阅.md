# 额外科学权重保存方案：独立科学覆盖审阅

本审阅只读取保存方案、冻结A选择/registry、主72端点inventory及C active registry/proof路径元数据；未读B/C/behavior测试分数、任何大checkpoint或权重TAR，未调用adapter、导出、GPU或新评分。原方案、data_assets正在开发的adapter均未修改。审阅对象为[保存方案评估](额外科学权重保存方案评估.md)，当前来源SHA及18项精确映射见独立JSON收据。

结论：**作为“A验证选λ的final政策＋C完整final对照”的优先保存方案，覆盖合理，18/15及63/条件57计数正确。它不是全部科学训练端点的持久权重备份。** 以下边界应写进最终manifest/交付声明，不必因此扩展导出scope。

## 需要补明的覆盖边界

1. 原方案第5/26行的A映射已逐项复核：B1=.05、B2=1、B3=.1、B4=M=5、C=1，每方法三seed。只有B1三项逻辑`lambda_sweep_...`映射到`formal_deterministic_B1_s{11,22,33}_b0p05_w0p05__final`，主inventory均durable、10M/.5M且已有完整指纹/source checkpoint SHA。其余15项是各自λ下的实际新run，不能改指向同方法主λ=.05，也不能借用主best。JSON保留全部18个condition→actual run映射；复用的是weights，A逻辑metadata仍要单列。
2. **A网格覆盖是33/126 final，不是126/126。** 主包已有六方法λ=.05的18项，A所选18项与之仅B1三项重合，故并集33，其余93个A final权重不在此增量保存方案中。全部126的配置、选择记录、日志、已授权统计应继续保留；但未打包权重不能宣称无需重训即可重做全部七λ推理。A不是新增18次训练：三主复用不加科学seed或物理训练成本；15新增权重也不增加科学实验条件。
3. **C仅保存63 final；冻结的C final+best评价不意味着best已持久保存。** 410M/1B分别8方法×3seed=24（B0/B1/B2/B3/B4/D/M/方法C）；2.8B为5方法×3seed=15（B0/B1/B2/B4/M），没有B3/D/方法C是既定scope，不是漏档。三模型C的best最多另有63个逻辑端点，本方案未承诺新增这些权重；若某best真与final相等，仍须端点绑定的独立full-state证据才可引用。B60选库变异、其余A候选和pilot权重也不在额外包scope中；不能称全部研究权重已持久化。

## 选择身份不能混用

A选择JSON SHA固定`9548085fc18278f69fad584b67485bceb5193a18b10c78f516f6b09b4fa4e477`，完整126条件、42候选后，按final共同曝光的三seed平均验证`S=delta_target+.5(delta_C4+delta_Wiki)`，每方法共享一个λ。它不是逐seed选λ，也不是沿时间选checkpoint，记录明确`selected_by_best_checkpoint=false`、`selection_uses_test=false`。建议kind命名`validation_selected_lambda_final`，保留共享λ、source selection/grid SHA、actual run、10M/.5M实际曝光。

主72 inventory则是36条件各final+target-validation-best；best是在同一已固定配置轨迹上按target验证NLL选时间点，真实曝光可小于10M。二者selection rule、候选集合、聚合seed与曝光不同，不能统一写“验证集最佳权重”。主36 best包不能替代A所选final，也不能用A所选λ覆盖主best身份。

## C alias成立的完整条件

原方案第5/27/28行已经正确要求源绑定证明，需在实际manifest落实到**同模型、同phase、同seed、同final端点**的每对`bitwise_model_state_equal=true`，双方checkpoint文件SHA与完整model-state fingerprint、registry/config/snapshot及实际曝光均绑定；`completion.status=passed`或audit通过单独都不等于权重相等。best等价证明不能代替final，整checkpoint SHA不同也不妨碍model-state确实相同。

本次审阅时两模型的completion/audit/final proof文件均尚未发布，因此**当前可确认C别名为0，57只是条件情形**：若六对final均相等，21+21+15=57份新增编码；否则保留相应D文件，最多63。原方案无alias额外约12.01GB的上端估计与3×(410M+1B raw bytes)×已观察高压缩比的算术一致，仍非跨模型体积上界。

D每个逻辑条件自己的config/counters/provenance/metadata、实际训练费用和seed身份都保留；仅weight payload引用B4。也不跨main_v3与data_extended、10M与100M/25M、不同模型/seed或未证明端点做alias。主72已有66物理权重/6alias是独立既有事实，不能挪作C新phase的相等证据。若六对未来全部通过，增量A+C为15+57=72份新编码，加主66为138份物理payload；这是条件容量计数，不是138个独立科学训练重复。

## 离线恢复与Adam边界

原方案第18/29行的“各逻辑端点独立metadata、不含optimizer、不冒充完整resume”科学表述正确。建议进一步写清：恢复的是供推理/评价或作为新训练起点的model-only权重，**不能据此续接原Adam动量及完整训练路径**；即便保留config、counters、部分RNG等metadata，也不足以证明完整optimizer/stream/resume状态复现。可以从恢复权重另建优化器开始一个新训练流程，不能把它称为原run的精确续训。

A/C410M引用主持久base是合理去重，但最终必须绑定base所在TAR SHA、准确member/base tensor SHA、config/tokenizer和离线提取说明，不可仅给`/tmp/...`绝对路径或可变Hub revision。1B/2.8B的各自pinned base、恢复所需config和codec来源也应进入可验证依赖闭包。保存权重本身不等于保存完整再训练所需训练数据/pool/bank；相关数据和来源manifest的保存状态要另列，不能由weight包覆盖声明代替。
