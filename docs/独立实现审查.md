## 影响结果的关键路径

| 检查项 | 独立核对结论与证据 |
| --- | --- |
| 因果移位 | 训练 CE 使用 `input_ids[:,1:]`，上下文 logit 位置为 0 到 L−2；最后一个 logit 不参与损失。训练与评估均要求相邻两个 token 的 attention 有效。部分预算切片保留左侧上下文，以 prediction mask 只计入新增预测位置，没有将同一位置作为新曝光重复计数。 |
| KL 方向与精度 | `objectives.py:71–85` 是全词表 `D_KL(teacher || student)`，梯度为 student probability 减 teacher probability；教师显式 detach。评估的两个 log normalizer 也覆盖全词表，词表切片只控制内存。softmax、logsumexp 与 KL 算术转 FP32；模型前向仍按协议采用 FP32 权重上的 BF16 autocast，应称“全词表 KL”，不能称“全 FP32 前向”。 |
| 教师冻结 | `train.py:369–374` 从同一固定初始模型加载教师，设 `eval()` 和 `requires_grad_(False)`；教师前向在 `no_grad()` 中。恢复仅载入学生及优化器，教师保持固定初始 checkpoint。 |
| 梯度累积与 λ | `train.py:566–599` 对每个目标 microbatch 的损失和除以该步实际目标预测 token 数，对回放损失和除以该步实际回放数，再乘 λ。各 microbatch backward 后只裁剪并更新一次；尾步同样用实际数。没有重复除 accumulation steps，也没有将两类 token 合并成一个均值。 |
| 回放预算 b | 累计需求为 `floor(target_exposure*b)-already_replayed`，避免逐步取整漂移。因此 b 控制累计计算曝光，λ 控制归一后回放项权重；回放单 token 相对目标单 token 的系数约为 λ/b，并非 bλ。库容量 K、实际独特曝光和重复曝光分别记录。 |
| 同 seed 公平性 | 目标流使用私有 torch Generator，回放流使用另一 seed；LR 仅按目标曝光推进。16 个真实 v3 λ 校准运行均为 2,000,000 目标 / 100,000 回放预测 token，目标流 trace 全部为 `af677c68…058f0`。这直接排除了本次校准中不同方法读到不同目标流的问题。非确定性 CUDA kernel 仍可能产生通常的数值差异，不能把 seed 相同宣称为跨硬件逐位可复现。 |
| 模型版本 | 三个正式生成池及其 banks 均指向 Pythia-410m commit `9879c9b5f8bea9051dcb0e68dff21493d67e9d4f`。本地权重下载 manifest 有文件 SHA256；生成统计绑定源池 SHA，选库再核对源池 SHA。训练日志的 model revision 与外部冻结 manifest 应一并归档，本地路径的 `revision` 字段本身不校验目录内容。 |
| 选择与测试隔离 | v3 协议明确先按目标验证 NLL 选共享 LR，再按预声明的三个语料 ΔNLL 合成分数、跨 B1–B4 平均选共享 λ。三个验证 tensor 的实际 SHA 均匹配协议。旧 v2 校准被标为探索性，v3 改 LR 后 16 个 λ 组合均重新训练。正式应使用预定固定目标曝光终点；保存的最佳验证模型不能未经声明替代该终点。 |

## 数据与实际库审计

主训练 v2 与评估 v3 保持独立路径。v3 由文档集中度检查触发，未使用测试损失：FineMath/C4 每个 heldout 为 1024 个 512-token 块，每篇至多 4 块，最大单文档权重 0.390625%。精确文档/块检查、训练到验证/测试的 13gram≥20% 整篇剔除，以及验证到测试的优先保留验证规则均有版本审计。WikiText 使用官方文章重建，未改为逐行文档。

本审查新增了全部正式生成候选池到六个 v3 heldout 的直接检查，而非仅依赖原始训练语料去污染。三个 seed 的整块重复均为 0，13gram 重合比例达到 20% 的块均为 0，最大比例为 6%；见 [生成池与 heldout 审计](../artifacts/assets/independent_generated_eval_overlap_audit.json)。该审计不涉及模型预测或测试损失。有限长度的精确 token ngram 检查不保证语义独立，也不能判断教师原始预训练时是否见过评估文本。

三个正式生成池的整块重复率均为 0，`generated_random` 与 `generated_dedup_random` 的选择 indices 和 chunk hashes 完全相同。因此 B4D 是内容相同的一致性消融，不能用这些结果估计“去除实际重复”的干预效果；若只运行并别名复用，应明确不是新增的独立训练重复。NLL 分层采用等频层、比例配额及最大余数取整，聚类使用 L2 归一特征和确定性空簇补位；这些规则实现了协议，却不自动保证梯度代表性或 retention 改善。

## 非阻断问题与解释约束

1. **恢复后的成本不是实际消耗的完整账本。** `train.py:460–478` 在序列化 counters 后才累加本次 checkpoint 写盘耗时，因此恢复会遗漏该次 durable checkpoint 自身的写盘成本；checkpoint 之后失败并重算的工作也被逻辑 counters 回滚。参数、优化器和曝光恢复不受此影响。若发生恢复，论文的总资源成本应采用进程/调度器外部 wall time，并保留归档事件及失败开销；不要把 committed-path counters 当成全部实际消耗。恢复期间还允许修改评估/保存节奏，正式比较应保持冻结节奏，避免事后改变最佳模型候选集合。

2. **KL 的零附近精度。** 评估会保留 `kl_min_before_roundoff_clamp`，然后将每个预测位置的微小负 KL 截为 0。这样在几乎相同的模型间会产生微小向上偏差；不应把该数值地板解释成真实遗忘差异。教师自比较复用 logits 有助于检查精确零，重要结论仍应远大于记录的 roundoff 范围。

3. **共享准备成本只计一次。** 每 seed 的生成池由生成方法共享，联合教师 NLL/特征统计只运行一次；聚类计时已包含于选库 wall time。训练教师前向计时嵌套在 training seconds，评估教师与 KL 算术嵌套在 validation seconds，源码明确 `nested_timers_are_additive_costs=False`。不得把这些子计时再加到父计时，也不得把“生成+选库”的公共准备费对每个 b 重复累计后当作一次实际总开销。方法独立部署成本与本次共享实验实际成本应分别说明。

4. **抽样和推论边界仍然存在。** FineMath 仅覆盖 64 shards 中的 4 个 shard 顺序前部，C4 仅使用单训练 shard 与单官方验证 shard 的部分文档；短于一整块的文本被排除。文档 cap 降低长文支配程度，也改变了评价的长度权重，不能宣称全语料无偏估计。C4 并非 Pythia 的原始 Pile 预训练集，数学 NLL 不是数学推理正确率。文档 bootstrap 衡量固定模型下文档抽样波动，不等于训练 seed 不确定性，三个 seeds 的变异应独立报告。

5. **extended 不是新的独立测试。** `data_extended` 与主数据沿用相同来源、文档哈希 partition，训练集包含主训练集，评估与主评估存在明确文档/块重合。因此它只能作为有关联的样本规模与覆盖稳健性检查，不能算第二次独立测试或扩大独立样本数。expanded training 对旧 v3 heldout 的新增近重复另有审计：FineMath val/test 为 29/37 块，C4 test 为 6 块；如启用扩展训练，必须使用配套 extended heldout，不能直接复用主 v3 指标。

审查只新增本文及机器可读审计证据。当前无需修改损失、预算、数据或选参协议；正式冻结应把本快照与最终运行源码哈希共同保存，并在结果表中保留上述成本和统计边界。

## 严格确定性与执行政策补充审查（04:35 UTC）

审查新 `execution.py`、训练设置与评估命令生成器，未运行 GPU，也未读取测试或行为分数。严格算法开关为 `warn_only=False`，CUBLAS workspace 在模型/CUDA 初始化前设置，TF32 两个开关与新训练配置一致；独立 CPU 标志检查前后 `torch.cuda.is_initialized()` 均为 false。新短 GPU probe 的四次梯度与三步参数 SHA 一致由训练工程师报告，完整训练一致性仍须单独检查。

发现并报告一个真实政策缺口：当前 NVIDIA Torch 提供第四个 `cudnn_sdp` 后端，fresh 进程默认 false；训练 auto 策略显式将它开启，而初版 execution 模块既不切换也不记录。CPU 反例中先开启 cudnn_sdp、再请求 math，最终 math 与 cudnn 同时开启，说明“math”请求不能保证独占 math，且初始评估与训练验证的允许后端集合不同。证据见 `artifacts/assets/execution_policy_independent_review.json`。主代理已要求修复配置、provenance 与比较函数，并另存匹配政策的初始基线。仅修正共享初始项不必自动重训：LR 按终点目标 NLL 排序，λ 分数中初始项对各候选是共同常数；前提是训练内验证设置保持一致。

分析模块相应增加生产 active 门禁：初始评估必须有执行 provenance；验证轨迹与初始验证逐项匹配，未来测试 JSON 也匹配初始测试执行政策，同时核对模型权重 dtype 与全部四个 SDPA 开关。只记录“auto”不等于证明实际选择了哪一个 kernel，结论应表述为相同允许集合与相同严格设置，结合数值 probe 和完整同库对照，而不臆测所有运行都用了 Flash。

评估队列脚本正确拒绝非 active/formal/未完成条目，固定同一模型、精度、后端政策、heldout tensor SHA，并按验证轨迹记录 best 的真实曝光。初审曾提出 checkpoint size/mtime 不能替代内容 SHA，以及 config 完全相等会拒绝科学设置未变的 resume/device override。主代理随后报告已改为流式完整 checkpoint SHA 和科学字段比较，并保留实际执行配置；这些旧建议不再列为未解决缺陷。队列内容与源码 hash 证明的是准备快照，真正执行时仍须防止被覆盖或误复用旧输出。
