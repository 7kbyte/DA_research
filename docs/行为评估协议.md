## 零样本输入与候选评分

不使用 few-shot、chat template、系统提示、答案字母、任务解释或随机采样。PiQA 上下文固定为 `Question: {goal}\nAnswer:`；两个候选保持原有 `sol1`、`sol2` 顺序。HellaSwag 严格按官方处理：`ctx_a + " " + ctx_b.capitalize()`，前接 `activity_label + ": "`；对上下文及四个 endings 做官方 `strip`、`" [title]" -> ". "`、去除方括号片段、一次双空格替换。不做额外清洗。

每个候选在上下文后接官方默认的一个空格。对整段 `context + continuation` 联合分词，再按单独 context 的 token 长度切分；如 context 末尾有空白，先按官方编码规则把末尾空白移入 continuation。Pythia 使用固定 tokenizer revision `9879c9b5f8bea9051dcb0e68dff21493d67e9d4f`，不自动添加 BOS/EOS。只有空 context 才用官方 prefix token（Pythia EOS/BOS 0）；两个任务均非空 context。

评分为候选所有 token 的条件 log-probability 之和，仅计 continuation，不计 prompt 或 padding。模型 `eval`、`inference_mode`，FP32 weights + CUDA BF16 autocast，与主实验一致；log-softmax/累计采用 FP32。最长上下文固定为 Pythia 原始 2,048 token；如超限，只左截 context，保留完整 continuation，并逐项记录截断量；若 continuation 本身超限则报错，不静默丢题。

## 官方指标与迁移

两个 task YAML 都同时声明 `acc` 和 `acc_norm`，**没有唯一的 primary/default metric 字段**。root 已在没有查看任何真实任务结果时明确冻结：两个任务均以 `acc_norm` 为项目主展示指标，`acc` 为并列辅助指标。这是项目的预注册展示决定，不声称官方指定了唯一主指标；不看结果选择较好者，不把 token 平均 logprob 冒称官方 `acc_norm`。两套 score 的 C→W / W→C 分别统计，禁止混用归一化方式。

`acc` 取总 logprob 最大的候选；`acc_norm` 取总 logprob 除以官方 choices 文本的 Python 字符长度（不含额外分隔空格）后的最大候选。该长度不是 tokenizer token 数，也不是 UTF-8 byte 数。完全相同时按原始候选顺序选择第一个。两个任务分别取逐题正确率平均，不给出跨任务合并分数。

每个 checkpoint 的逐题 JSONL 保存 stable item_id、gold、题目/候选 fingerprint、每个候选总 logprob、token 数、字符长度、两个预测及正确性。与同一初始模型的逐题结果严格按任务、item_id、fingerprint 和 gold 配对，分别统计：初始正确→适应后错误（C→W）、初始错误→适应后正确（W→C）、C→C、W→W；同时报告 C→W / 初始正确数、W→C / 初始错误数及 `(W→C - C→W) / N`。两个指标各算一组，保留迁移题目 ID。平均 accuracy 变化为零也可能同时存在遗忘和获得，不据此声称所有原有知识均保留。

## 冻结与验证

主实验冻结之前只运行 CPU 合成模型的科学不变量 tests；如需要真实数据 smoke，最多每任务 8 题、明确 `smoke` 和 `complete_split=false`，不用于模型选择或正式结论。正式运行使用完整 split，并且所有方法、seeds、初始模型共用相同文件与 prompt fingerprint。行为分数不参与 checkpoint 选择，checkpoint 使用主协议已经冻结的验证选择结果；不根据结果更改 prompt、预处理、长度归一化或报告列。任何修复都先记录原因并使所有方法重新按同一版本评价。
