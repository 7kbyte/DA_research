# 论文写作与答辩提纲（主实验与补充A/B完成版）

本稿依据已经完成的主36训练、补充A126条件和B60条件及各自冻结heldout NLL测试；B复用主v3测试文本与配套initial，不是新增独立测试样本。C与行为结果仍待完成，后续只能填入真实完整结果，不能把准备好的配置写成已验证结论。主数字和证据入口以[研究报告](../研究报告.md)、[主NLL讨论](主NLL测试结果讨论.md)及[B完整测试解释](补充B_完整60run测试结果解释.md)为准。

## 论文应当回答的核心问题

问题不是“能否发明生成回放”，而是：在相同目标训练量、有限回放库和明确损失权重下，来源、目标函数与选库规则怎样改变适应和保留？这使正结果与负结果都有解释价值。应把研究定位为受控实证比较，不将自生成、forward KL、NLL分层或聚类包装成新算法。

主线可组织为三个问题：同一来源下CE与KL有什么区别；相同目标函数下C4和自生成文本有什么区别；同一生成池、相同库容量下分层/聚类是否优于随机。预算与实际成本贯穿三个问题，不能只在结尾附一个训练耗时总数。

## 建议的论文章节

| 章节 | 需要建立的论证 | 当前证据入口 |
|---|---|---|

| 方法与预算 | 分开定义K、累计b与λ；给出八组控制、完整KL与CE的关系 | 方法推导、工程约定、冻结配置 |
| 数据与实现 | 文档先划分后分块、去重和评价权重；数值空对照为何必要 | 数据manifest、正式运行审计、D/B4证明 |
| 主实验结果 | 固定10M独立测试、全部六配对、两个旧域、三seed及不确定性 | primary_nll_v2/final与可读区间表 |
| 轨迹与敏感性 | 验证选点及其独立测试，完整b曲线；后续A/B/C各自独立身份 | best、验证轨迹、补充阶段完整输出 |
| 讨论与成本 | 能支持哪些解释，哪些只是探索性机制；共享/独立部署成本 | replay-fit、权重分解、实际成本分项 |
| 结论与局限 | 回答原RQ，明确分布、数据量、模型与重复数边界 | 只引用前面已完成证据，不补写未做结果 |

结果章节宜先呈现独立测试，再用验证轨迹和探索性诊断解释；不要按“先发现什么、后来又试了什么”的工作日志顺序代替科学论证。旧非确定性运行保留在工程诊断中，不能混入正式方法表。

## 十分钟答辩的叙述顺序

1. **1分钟：问题与范围。** 数学文本继续训练，测目标NLL增益及C4/WikiText损失变化；不直接测数学推理或全部旧知识。
2. **1分钟：文献与贡献定位。** 说明最接近的生成回放/KL研究和SSR已有步骤；突出当前有限库、三因素与实际成本的控制比较。
3. **2分钟：设计与可信度。** 用八组表解释来源/目标/选择；解释K、b、λ；展示文档划分及D/B4空对照通过完整权重检查。
4. **3分钟：主测试与端点。** 展示六配对图：同来源KL减少两个旧域退化；M未稳定胜出；最佳点与固定10M终点不同，不能只保留有利端点。
5. **2分钟：预算、机制与局限。** 展示有限库CE拟合诊断及成本口径；说明三seed、文本代理、权重和受限采样的解释边界。用A完整λ曲线说明共享超参数的适用范围，用B说明库组成稳定不等于端点稳定；C和行为仍待完整结果。
6. **1分钟：回答原问题。** 按来源/目标、选择、预算三项逐一回答，保持结论条件化；未来工作对应证据缺口，不再许诺必然提升。

## 常见追问与可用回答

**为什么不用原预训练数据？** 本研究把C4作为可取得的替代通用文本，Pythia实际来自Pile。因此B1/B2不是严格原数据回放。C4来源与C4评价同域，WikiText提供另一代理；两者都不足以代表所有旧分布。

**数学NLL下降是不是推理能力提高？** 不是。它说明固定tokenizer、固定文本和512-token块条件下，下一词预测更好。需要独立数学题与答案判定，才能回答推理能力问题，本次主实验没有提供这种直接证据。

**为什么b=.05不是混合数据中的5%？** b定义为回放预测token除目标预测token，所以总处理量中的比例为b/(1+b)，约4.76%。两项损失分别取有效token均值，平均回放权重另由λ控制。改变b也会改变单个回放token的相对系数、重复率和估计噪声。

**既然生成CE的期望等于KL加常数，为什么结果不同？** 恒等式要求固定参数/前缀，再对新的完整教师标签分布取期望。当前库有限且重复使用，训练后的参数依赖那些标签；硬标签梯度并不等于完整分布梯度。replay-fit只给出与有限标签拟合一致的探索性证据，没有证明全部C4/Wiki差异都来自这一机制。

**共享λ=.05与逐方法选λ为什么结论不同？** 两次比较回答不同问题。主实验按2M独立种子校准后的共同λ固定各组；A在10M完整七点网格上按相同验证规则为各方法选λ。B4−B2在共同λ=.05时C4遗忘差为+.0373，而分别选5/1后为−.0061；后者同时改变方法和λ，是完整选参政策比较。不能拿后者改写同λ来源效应，也不能归因于训练长度这个单一因素。B保持预先冻结的λ=.05；C按各自冻结协议执行，结果另报。

**保留与适应是否必然冲突？** 不必然。A中B4从λ=.05到验证所选5时，独立数学增益从.0086到.0757，两个旧域的损失增量也同时下降。这支持当前有限目标库和给定训练条件下二者同时改善的观察。完整λ曲线到10又出现退化，不能由一个改善区间推出权重越大越好，更不能据文本NLL声称所有能力都增强。

**分层没有稳定提升，课题是否失败？** 原问题就是检验何时有用、何时无效。M确实约束了教师NLL组成，C改善了所定义特征距离，但这些代理不自动保证最终保留。应报告完整三seed和所有配对，而不是事后改算法直到出现正结果。完整B60中，M的bank均值teacher-NLL更稳，但两种K×三个token端点的六格sample SD均未低于B4。这里只观察到10draw的样本SD，不证明总体方差更大，也未直接测所有梯度方差。见[B测试与组成解析对照](补充B_完整60run测试结果解释.md#与validation和事前bank组成解析的关系)。

**B的十次选库能增加主实验的训练seed数吗？** 不能。B固定pool=11、train=11，n=10是selection seeds1001—1010的条件bank draws；不是十个独立训练/生成seed，也不能和主三seed合成十三个重复。同标签配对不保证不同算法消耗相同随机数，不能称严格CRN。全部[60个个体](../results/supplement_B_test_review_v2/all_60_endpoints.csv)均保留。

**K196的M均值更好，是否足以宣布分层有效？** 其M−B4的G/C4/Wiki均值差为+.004052/−.004415/−.006274，有利个体7/7/8个；K20三个均值方向却相反，且K196的端点SD也未降低。这限定于一个pool、一个训练seed和冻结λ=.05，不能外推稳定优势或按test事后选K。见[同标签配对差及sample SD](../results/supplement_B_test_review_v2/paired_six_metric_statistics.csv)与[方向计数](../results/supplement_B_test_review_v2/direction_counts.csv)。

**D与B4相同还有意义吗？** 生成池没有精确整块重复，D没有实施有效去重干预，所以不能估计去重收益。但相同库、相同训练流的控制暴露了早期数值不一致；重跑strict后，三个seed完整训练及权重均相同，支持当前平台的数值可比性。D不能与B4合并为六个独立重复。

**为什么最终点收益弱，而best较好？** 所有best均早于10M，随后同一有限目标库继续重复训练。独立测试中36个配置的best在三个NLL指标上都好于各自final，支持本设置中的收益退化判断。best按验证选择、曝光不一，不能替换固定10M主比较；实际执行过完整训练的成本也不能抹去。

**5000次bootstrap是不是足够大的样本量？** 不是。5000是重采样次数；文档数是466/595/60，主pipeline seed只有3。文档区间条件于固定检查点和当前文档样本，不覆盖重新训练、生成、选库和调参的不确定性。多项逐一95%区间也不是全研究统一95%的显著性保证。B中K196的M−B4在draw1001/1005的token ΔG分别为+.018049/−.024406，各自条件文档区间虽窄，bank draw方向仍相反；文档区间不能替代选库sample SD。假设文档独立/可交换重采样也可能受同源内容相关性限制。见[逐draw条件区间](../results/supplement_B_test_review_v2/conditional_paired_document_CIs.csv)。

**等文档与token加权结果符号不同，该选哪个？** 两者回答不同平均问题，已经预先约定同时报告。当前保留更多块的文档组在final的平均数学增益较低，token加权更重视这些文档。测试后分解说明这一加权关系，但不证明长度因果效应，也不能按哪个结果更好看临时挑口径。B六条件的token/doc均值排名相同，绝对增益仍有明显差异：例如K20/B4的G为token−.000243、等文档+.021654；冻结样本中保留更多块的文档在token口径下权重较高。见[六指标统计](../results/supplement_B_test_review_v2/six_metric_statistics.csv)与[文档权重分解](../results/supplement_B_test_review_v1/target_doc_weight_decomposition_24.csv)。

**4卡并行耗时与成本怎样对比？** 区分每项进程墙钟、训练/验证等父项、嵌套教师时间，以及整段研究历时。共享生成池只计一次，D/B4确实各自训练的成本都计入，等价证明后才省去重复评价。实际占用、利用率和GPU能耗另有监控，不能把并行进程时间总和说成用户等待时间，也不能把利用率积分说成FLOPs。
