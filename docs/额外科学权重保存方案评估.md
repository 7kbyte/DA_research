# A选定端点与C全部final权重：CPU容量及尾部时间评估

本文件仅为方案评估，未启动export、预留写入、共享归档或GPU任务；不依据任何测试分数挑选权重。A选择使用已经冻结的验证选择JSON，C保留三模型完整final条件，不改变训练、选参、horizon或scorer。数字和来源SHA另存 [额外科学权重保存容量评估.json](额外科学权重保存容量评估.json)。

A的18个选定final中，B1三seed的λ=.05已经在主final持久包中，新增15个unique；其他15个不因其主测试表现而筛选。C为410M/1B各24及2.8B的15个逻辑final，共63；只有对应phase的完整审计及逐seed、逐源checkpoint绑定的D/B4模型位级相等证明通过，前两模型才能各引用3个B4，合计57unique。proof的 `status=passed` 只表示审计完成，不能代替每对 `bitwise_model_state_equal=true`；若不相等则保留两份，最多额外6unique、约12.01GB。

估计依据是已完整验收的45个410M主端点：每个FP32模型1,621,336,064字节，ZIP/raw实测.69273–.70600，编码CPU共3,113.19秒，包含encode→decode→原始uint8逐tensor比对及两个TAR的总wall为4,467.71秒。按原始模型字节线性外推，编码约42.67秒/GB、完整工作约61.23秒/GB。该区间来自410M/10M的两个包，**不是**1B/2.8B或100M训练的预测区间，也不是压缩体积上界；必须用每个新模型的首个CPU往返实例更新预算。

只用pinned配置在CPU的meta device建立模型，未分配真实模型权重、未forward，核实410M/1B/2.8B的state分别为405,334,016、1,011,781,632、2,775,208,960个FP32元素，即1.621/4.047/11.101GB。与safetensors头部剔除旧版attention mask/rotary缓存后的结果一致；不能把base里这些U8缓存误算成训练参数。

GB为十进制；GiB为2^30字节。每包上端已加32MiB小元数据余量。A/C410M不再重复保存已有913.5MB的410M base及公共tokenizer，而明确引用主持久包中固定base SHA及提取位置；恢复不依赖再下载。1B/2.8B各自新增pinned base只带一次，表中已计入2,090,701,528和5,684,693,096字节，config及必要恢复文件随该模型包携带；后续同模型包只引用同一离线base身份。每个逻辑条件均须有自己的config/counters/provenance/实际曝光及metadata记录，即使weights引用alias。

全部A+C预计222.43–226.68GB，即约207.16–211.11GiB。10:03实测共享可用129.65GB，已分配报告预留并不包含在此available值中；再保留2GiB空闲后，全部方案仍缺约99.18GB，且这未加跨模型压缩不确定性的容量余量。A+C410M+C1B的上端合计103.40GB，当前容量理论上可覆盖；余量不足以再容纳完整C2.8B。建议先按这些完整分组顺序取得独立预留与单例证据，C2.8B须另获约123GB的整包容量后才能承诺持久保存，不消费1GiB/3GiB报告保底。共享free会被其他用户改变，这不是空间已获保证。

scratch实测可用约25.25TB。若完全沿用当前exporter保留全部ZIP、每个恢复模型及外层TAR，四批额外scratch约755.45GB，其中C2.8B约407.38GB；现有空间可承受，原checkpoint始终保留。可日后选择在位级验收后仅清理派生恢复临时文件以降低scratch峰值，但无需为本方案删原checkpoint或已发布包。

现有 **codec格式可原样复用**：整数XOR、byte-plane、每tensor原始SHA与全模型fingerprint均不依赖模型规模，CPU线程仍2、单worker顺序。现有 `export_remaining_primary_endpoints.py` 入口硬绑定主36/410M/10M及main NLL manifest，不能把C或A伪装为main来运行。需要一个保留phase/model/data身份的薄adapter，复用codec、完整metadata往返与TAR验收helper，分别执行以下门禁：

1. A：绑定完整126验证选择SHA及全部来源身份，选定18个实际run ID；三份已持久B1通过既有模型fingerprint/源checkpoint SHA证明复用，新增15个依次encode→decode→全uint8比对。
2. C410M/1B：该模型完整24条件完成，匹配active registry、协议、输入snapshot、实际最终曝光及执行policy；再验证训练agent产出的completion/audit/final等价proof及其SHA。不等其他模型，但不能对本模型的partial cohort导出成完整包。
3. C2.8B：完整15条件完成，通过独立模型内审计，固定25M曝光，不借用100M或410M身份。任何alias都必须由当前源checkpoint及端点绑定的证明支持。
4. 每个新模型先完成一例真实CPU位级往返，核实际压缩率、RAM与时间；随后仍按全部冻结条件导出，不基于结果增删。所有包绑定source stat/SHA、原config/counters和模型fingerprint，不含optimizer，不冒充可完整resume训练。

CPU顺序外推全批约316分钟，约5.27小时，可在各模型完整gate后逐批进行。最大尾部是C2.8B：gate完成后encode/往返/外层TAR约170分钟，再按预算final包14.65GB/108.24秒的已测发布速度估约15分钟，名义上约3小时05分钟；该发布估计已包含源SHA、写入与前缀重读，不能另把内部计时重加。审计gate本身、系统竞争和压缩率变化尚需额外余量。

若容量提前预留且2.8B于00:00完成，名义可在03:05完成发布，距03:26截止仅约21分钟，不能承诺稳妥。按CPU慢50%、发布慢一倍、另20分钟审计/交付余量计算，需约5小时05分钟，完整gate应在约22:21之前具备。若仍用每轮2GiB、轮间30秒的受控扩容器，从零准备约123GB还需约30分钟；应在训练期间、已有root授权及足够容量时提前完成，不能将这一步漏算进最后尾部。root可据实际训练进度、单例和容量作决定；本评估没有启动任何新工程执行。
