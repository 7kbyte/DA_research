全部交付均不含 optimizer，是无损 model-only 权重及元数据，不是完整训练恢复包。原始 checkpoints、ZIP 和已有 TAR 全部保留。

工具为 `scripts/archive_model_weights.py`，实现为 `src/replay_study/weight_archive.py`，格式名 `replay_study_fp32_xor_byteplanes_zip_v1`。本工具只在CPU运行，线程参数限制1–4；不加载GPU、不修改原checkpoint或固定基座。以下保留格式说明与首包历史验收/发布收据；历史的 scratch-only 文字描述的是发布前阶段。

对每个FP32训练tensor，以固定safetensors基座的同名tensor转换为FP32作为参考；将双方内存位型解释为uint32，逐位XOR。每个默认4MiB块再排列为低字节到高字节的四个连续byte plane，用ZIP中的zlib/deflate压缩。全过程不对训练权重做浮点减法、舍入或有损量化。XOR与字节排列均可逆，恢复出的NaN payload、符号零和其他位型也须保持一致。

archive内metadata绑定完整base文件SHA、完整源checkpoint文件SHA、源config/counters/provenance/验证记录、原checkpoint_kind及selection（若存在）、每tensor的训练raw SHA和基座FP32转换raw SHA。恢复文件的通用类型为 `model_only_lossless_xor_restored`，来源类型保留在provenance中，不会把best来源误称为final。全模型fingerprint与 `scripts/audit_formal_runs.py` 完全同约定：按tensor名排序，依次哈希JSON(name,dtype,shape)及原始tensor字节。decode先核对base文件SHA，再逐tensor核对转换位型、恢复raw SHA，最后核对完整model fingerprint，成功后才原子提交恢复文件。压缩输出和恢复输出均拒绝覆盖已有文件。

交付内容是**无损model-only权重及相关元数据**，采用评估脚本已有的model_state字典格式。源latest.pt还包含optimizer等训练恢复状态，压缩包不保留这些额外状态；因此压缩率用archive大小除**FP32模型原始字节**，不把省略optimizer冒称额外压缩。恢复文件可由现有 `load_pinned_model(..., checkpoint=...)` 严格加载，用明确提供的新基座路径替代记录中的历史scratch路径。v1要求little-endian CPU及FP32训练model_state。

```bash
# 参数--threads在子命令之前；以下均为新输出，不覆盖原权重。
python scripts/archive_model_weights.py --threads 2 encode \
  --checkpoint /path/to/latest.pt --base /path/to/model.safetensors \
  --output /scratch/delivery/weights/run.xor.zip \
  --expected-model-sha256 AUDITED_MODEL_STATE_SHA

python scripts/archive_model_weights.py --threads 2 decode \
  --archive /scratch/delivery/weights/run.xor.zip \
  --base /path/to/the_same_model.safetensors \
  --output /scratch/delivery/weights/run.restored.pt

# 单例交付审查需要与仍保留的原checkpoint实际逐字节比较，不只看浮点相等。
python scripts/archive_model_weights.py --threads 2 verify \
  --checkpoint /path/to/latest.pt --restored /scratch/delivery/weights/run.restored.pt \
  --archive /scratch/delivery/weights/run.xor.zip \
  --output /scratch/delivery/weights/run.roundtrip.json
```

encode/decode各自生成耗时、大小、SHA和CPU线程数报告；verify以原始uint8序列逐tensor比较，避免浮点相等对NaN和符号零的错误判定。6项格式测试已覆盖特殊位型/空tensor/分块往返、坏base拒绝、审计fingerprint不符、best来源选择元数据，以及截断ZIP/损坏payload均拒绝且不提交恢复文件。真实单例 `artifacts/assets/lossless_weight_single_example.json` 的archive为1,143,733,212字节，占FP32模型原始1,621,336,064字节的70.5426%。

`scripts/export_primary_weight_delivery.py` 使用单worker和2个CPU线程，每份encode→decode→与保留原checkpoint全部uint8字节实际比对后，才纳入交付manifest。三份D只在主36审计证明同seed完整model fingerprint与B4相等后引用B4；每个逻辑条件仍保留自身config/counters/provenance与原checkpoint SHA。首个旧单例ZIP使用兼容v1位型格式，其原encoder源码及SHA另外留档；新decoder复验全部位型，manifest明确旧metadata可选字段缺省，而原latest确实没有这些字段。
