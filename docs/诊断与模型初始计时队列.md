以下清单只经 CPU 准备和 `--verify-only`；生成、校验清单不授权运行。执行均沿用冻结的 `run_frozen_evaluation.py` 和评分 core，无新 helper 修订。

1B/2.8B 原始模型计时使用 `configs/planned_model_behavioral_timing_v1_queue.json`、`docs/planned_model_behavioral_timing_v1_manifest.json`。只有两个 initial jobs，适应后端点为零；来源是固定 revision/原始权重及三个已完成 LR pilot 的实际执行 provenance，不声称对应 formal 已完成。batch 分别16/8，context2048，主 acc_norm、辅助 acc 均按原冻结任务定义。若某模型最终未完成正式对照，该 initial 仅计为诊断。CPU 证据在 `results/planned_model_behavioral_timing_v1_cpu_review.json` 和同前缀 `verify_only.json`。

baseline identity 与通用 v2 builder 完全同式，绑定 model assets、task/harness SHA、scorer SHA 和实际数值执行策略；后续正式 phase 的 `prior_plans` 可引用这份原清单路径及 SHA 复用 initial，不创建别名链。命令中的 frozen scorer `evaluation_role=formal` 表示完整任务 split，与训练阶段身份无关；清单明确 `formal_training_completed_claim=false`。只读耗时需从 execution attestation 和 master state 提取，禁止读取任务结果的 acc、choice 或预测。

replay-fit 使用 `configs/replay_fit_diagnostic_v2_queue.json`、`docs/replay_fit_diagnostic_v2_manifest.json`。每个 seed 的有序 bank/complement 独立分组：三个 initial，B3/B4 各三 seed 的 final/best 共12项适应后评分，总15项。每项 bank100156、complement899871 个预测 token；initial 复用 student logits，适应后额外 teacher forward，合计27000729 个单前向预测 token 等价量。best 实际目标曝光3270400、final10000000；完整物理训练成本仍按10000000计算，不能按 best 缩小或为两个端点重复计费。

replay-fit 是主 validation 之后指定的探索性诊断；complement 来自同一个生成 pool，不是独立 heldout。比较适应后减 initial 的 complement/bank NLL gap，再比较同 seed B3−B4，final/best 分层；不用于新选参或改库。数据协议绑定历史 checkpoint SHA；执行策略取当前 execution-matched 主 NLL 清单。执行前重新散列 checkpoint，不能只依赖文件大小/mtime。15项 `verify-only` 均通过，证据见 `results/replay_fit_diagnostic_v2_cpu_review.json`。早期 `replay_fit_diagnostic_v1*` 草稿没有发入 master，已被本 v2 取代，不能执行。

root 审查并明确授权后，在已有单层 master 追加；不要运行独立 GPU scheduler：

```bash
python scripts/manage_supplemental_queue.py append \
  --master-queue configs/supplemental_v1_queue.json \
  --phase-index configs/supplemental_v1_registry_index.json \
  --phase planned_model_initial_timing_v1 \
  --phase-queue configs/planned_model_behavioral_timing_v1_queue.json \
  --phase-registry docs/planned_model_behavioral_timing_v1_manifest.json

python scripts/manage_supplemental_queue.py append \
  --master-queue configs/supplemental_v1_queue.json \
  --phase-index configs/supplemental_v1_registry_index.json \
  --phase replay_fit_diagnostic_v2 \
  --phase-queue configs/replay_fit_diagnostic_v2_queue.json \
  --phase-registry docs/replay_fit_diagnostic_v2_manifest.json
```

两个 append 是不同授权事项。job 的 `expected_seconds` 只是排程 allowance，不是实测耗时、纯 GPU 时间或精度指标；teacher 子计时已包含于父 wall，不重复相加。
