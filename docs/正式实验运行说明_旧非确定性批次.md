## 已冻结的训练协议

8 组 B0/B1/B2/B3/B4/D/M/C × seed 11/22/33 共 24 组，B4/M 再加 b=.01/.10 × 三 seed 共 12 组，总计 36。每组处理恰好 10,000,000 target prediction tokens；全参数 FP32 权重，BF16 autocast；frozen teacher 同为 FP32 权重和相同 autocast；KL 为完整词表的 teacher-to-student forward KL，概率和损失运算为 FP32。

共享 LR=3e-5、replay λ=.05，由 pilot seed101 和 v3 validation 按预先规则选择，见 `results/pilot_lr_selection_v3.json`、`results/pilot_lambda_selection_v3.json`、`docs/hyperparameter_selection_protocol_v3_lambda.json`。原 v2 exploratory 记录保留，未用于最终正式选参。

microbatch=16、梯度累积=4，完整 step 为 64×511=32704 target prediction tokens，共 306 optimizer steps（最后一步精确截到预算）。LR 仅依赖 target exposure；同 seed 的全部方法使用相同目标数据流和 LR。每 50 steps 验证并在第 306 step 最终验证；`save_every_steps=0`，最终保留完整可恢复 checkpoint，验证过程中仅更新 target-validation NLL 最低的 model-only checkpoint。

每个 replay bank 容量及唯一容量 K=100156 prediction tokens（196×511），原始输入 token 100352。累计 replay exposure 为 floor(b×累计 target exposure)，因此 b=.01/.05/.10 的最终 exposure 恰为 100000/500000/1000000。部分 chunk 仅对实际分配的有效预测位置计 loss，前置上下文按实际原始输入另计成本；CE/KL 使用同样的 mask。λ 独立于 b。有效位置要求相邻两个 attention mask 均有效；最后位置 logits 不预测本 chunk 外的 token。

`coverage_accounting` 分容量、实际唯一预测位置覆盖、累计暴露和重复暴露。唯一位置按 exact input_ids+mask chunk identity 统计，不是不同词表 token ID 的数量。低预算 b=.01 的实际 replay unique coverage 为 100000，不能报成整库 K=100156；.05/.10 的重复暴露分别为 399844/899844。重复 chunks 在覆盖计量中合并有效预测前缀。

## 复现命令

在具有相同冻结输入和环境的新运行目录中，生成主配置的命令为：

```bash
python scripts/make_experiments.py generate --phase formal --protocol docs/hyperparameter_selection_protocol_v3_lambda.json --shared-lambda 0.05
```

该命令写 36 个配置、`configs/formal_registry.json`、`configs/formal_queue.json`，并生成正式输入 hash 快照；它自身不启动训练。主调度命令为：

```bash
python scripts/schedule_jobs.py --queue configs/formal_queue.json --state logs/formal_job_state.json --gpus 0,2,3 --deadline 2026-11-07T03:26:32Z --exit-when-idle
```

scheduler 对 state 文件持锁，使用 argv 调用而非 shell 插值；GPU 通过 CUDA_VISIBLE_DEVICES 分配，配置中的 cuda:0 指分配后进程可见的 GPU。它保留 PID/物理 GPU/日志/开始结束时间。状态为 running 时不接管任意 PID；原调度器结束后需先核对实际进程再恢复调度。

单项直接运行与断点续跑示例：

```bash
python scripts/run_train.py --config configs/formal/formal_B4_s11_b0p05_w0p05.json
python scripts/run_train.py --config configs/formal/formal_B4_s11_b0p05_w0p05.json --resume /tmp/grad-research-20261106/runs/formal_B4_s11_b0p05_w0p05/checkpoints/latest.pt
```

完整 checkpoint 含 model、AdamW、RNG、目标/replay stream 的 epoch/row/partial offset、计数和 validation trajectory。恢复禁止科学配置及输入 tensor 变化；如旧 events 比 durable checkpoint 更新，旧轨迹先归档，活动 events 回退到 checkpoint，避免恢复后的 exposure 重复计数。model-only best checkpoint 用于评估，不包含 optimizer，不能用于继续训练。

## 产物、成本与审计

大权重保存在 scratch：`/tmp/grad-research-20261106/runs/<id>/`。每项包含 config.json、events.jsonl、summary.json、checkpoints/latest.pt 与 checkpoints/checkpoint_best.pt。小 summary 原子同步至 `results/runs/<id>_summary.json`；任务日志位于 `logs/jobs/<id>.log`。持久化选择和权重副本由 root 统一安排。

成本主项为 setup_seconds、training_seconds、validation_seconds、checkpoint_seconds。training_teacher_forward_seconds 已包含于 training_seconds；validation teacher forward 与 KL arithmetic 已包含于 validation_seconds，不能再次加到总成本。CUDA 子计时为 event elapsed，CPU 为 perf_counter。peak_gpu_memory_bytes 是 PyTorch allocated peak，不是整卡进程外显存。

只读的进行中与最终审计命令为：

```bash
python scripts/audit_formal_runs.py --allow-incomplete --output results/formal_run_audit_partial.json
python scripts/audit_formal_runs.py --output results/formal_run_audit.json
```

最终审计核对 36 completed、10M 目标预算、三档 replay 精确配额、K 与实际覆盖、每步记账、同 seed 目标流/LR、v3 validation-only 选点、frozen 文件 hash 与嵌套成本。D/B4 同 bank 的三 seed 空对照比较全部训练/验证轨迹（atol=rtol=1e-5），最终另计算 model_state 字节指纹，区分数值接近与逐位相同。审计本身不计算 test loss。
