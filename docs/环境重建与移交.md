# 环境重建与移交

## 已验证的平台与重建边界

实际运行环境为 Python 3.10.12、NVIDIA Torch `2.3.0a0+6ddf5cf85e.nv24.04`、Torch CUDA 12.4、H100 80GB。包管理器按版本规范显示为 `nv24.4`，不是另一个 Torch 构建。当前依赖版本见 [reproduction_dependency_snapshot.json](../artifacts/assets/reproduction_dependency_snapshot.json)，实验执行策略和输入哈希仍以各正式协议为准。

[NVIDIA 官方 24.04 发布说明](https://docs.nvidia.com/deeplearning/frameworks/pytorch-release-notes/rel-24-04.html)列出相同的 Torch 源码版本与 CUDA 12.4.1。可从 `nvcr.io/nvidia/pytorch:24.04-py3` 开始重建，再安装本项目依赖。这个镜像建议依据官方版本对应关系；本次平台没有 Docker 命令，**没有完成在全新容器中的重建验证，也未取得平台镜像 digest**。同标签、不同驱动或硬件不保证逐位重复，应重新执行数值资格检查。

在具有匹配 Torch 的环境内执行：

```bash
python -m pip install -r requirements-research.txt
python -m pip install --no-deps -e .
python -m pytest -q
```

`requirements-research.txt`固定本项目直接使用及部分关键依赖的实际版本，刻意不通过 PyPI 替换 NVIDIA Torch；它不是全部传递依赖的带哈希锁文件。平台原有 cudf/protobuf、torchtext/Torch 依赖冲突记录在环境文件中；本项目未调用这两个包。不要仅为消除不相关包的提示而升级研究的冻结数值环境。

## 数据、模型与运行记录

移交归档携带实际 token 数据、回放库、统计量、冻结配置、源码、版本证据、分析结果和运行记录。`PACKAGE_MANIFEST.json`列出每个归档文件的 SHA256；`external_weights_not_included`明确列出未归档的 checkpoint 路径和大小，空 SHA 不代表已校验这些大文件。每份快照逐文件稳定读取，但运行中的多文件不构成同一瞬间的事务快照；正式交付会在相关写入完成后重新制作。

基础模型按 `artifacts/assets/model_provenance.json` 与 `extended_model_provenance.json` 的固定 revision 下载，并核对文件 SHA。训练配置路径需要通过 `scripts/reproduce_experiments.py relocate` 重定位；完整命令见 [README](../README.md)。解包的 `run_records/` 提供原训练轨迹、计时和摘要，不能把缺少大权重的记录目录当作可恢复训练的完整 checkpoint。

实际归档演练已从07:32持久快照解包并核验全部3925个成员，使用归档内未修改的helper完成来源×目标函数四组（B1/B2/B3/B4，seed11）的重定位及dry-run。固定基座取自已发布权重包，34项模型/数据及相邻manifest和10份冻结源码均核验通过。该演练在当前平台完成；尚未启动重训练，也不等于在全新环境中的复现。详情和状态见[归档复现QA演练](归档复现QA演练.md)。

由于共享盘曾多次写满，当前逻辑工作目录解析到本机 scratch。真正写入共享盘并校验成功的归档路径见 [durable_snapshot_latest.json](durable_snapshot_latest.json)。临时盘中的大型训练权重、下载缓存和报告渲染依赖不自动包含在移交包中。保留的 1 GiB 共享盘预分配文件用于最终空间不足时的归档，不应提前删除。

08:24 UTC另成功预分配3 GiB，用于最终代码、token数据、日志、指标和报告归档，实际文件长度与分配块均已核对，见[预留收据](final_results_storage_reservation.json)。它与原1 GiB后备文件、权重包预留分别记账。预留空间仍是空白文件，不代表最终内容已经发布；最终以成功发布的归档收据为准。
