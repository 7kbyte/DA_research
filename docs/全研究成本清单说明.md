运行方式：

```bash
python scripts/inventory_study_costs.py \
  --sources configs/cost_inventory_sources.json \
  --runs-root /tmp/grad-research-20261106/runs \
  --output results/cost_inventory_current
```

工具只在 CPU 读取训练 summary/config/events、显式 registry、显式 generation summary 和其他成本报告，不加载 checkpoint/tensor、不调用模型、不执行 test 或 behavior 推理，也不修改这些来源。唯一写入是指定输出目录中的 CSV/JSON。configs/cost_inventory_sources.json 明确指定每份 registry 的 primary/supplement/pilot/provisional/diagnostic 分类，以及少量历史未注册诊断目录的分类理由；工具不按目录名自动赋予科学资格。新增阶段需要扩充这份显式来源表，未知目录依旧显示 unregistered。

physical_runs.csv 按 resolve 后的实际目录去重。别名 registry、symlink 和项目内复制的 summary 只提供引用，不产生新的训练；registry_entries.csv 保留每条逻辑引用、alias 状态和是否观察到物理目录。尚未创建物理目录的计划 run 留在 registry 表中，成本不计零冒充已运行。若同一物理目录有冲突的非 alias 分类，会显示 classification_conflict，交由审阅，不随意归到主实验。

actual_target/replay_prediction_tokens 与计时只称 committed-path accounting。优先读取已有 summary/finish 或较新的当前事件路径的最后完整 counter；不用最大值，也不累加各 step counter。回滚后 counter 可以下降，归档的 events.pre_resume_*.jsonl 只留来源记录，不重加其中工作。没有 summary 的事件路径标明 in-progress-or-interrupted，而不假定它此刻仍有进程。active train_step counter 不声明已写进可恢复 checkpoint，counter_durability 会明确标记 not_checkpoint_verified。读取中的不完整最后一行、JSON 错误和发生变化的来源文件都留有标记；当前清单是逐文件观测快照，不能声称全研究在同一瞬间原子冻结。

setup_seconds、training_seconds、validation_seconds、checkpoint_seconds 是四个父计时。known_parent_component_sum_seconds 仅加这四项中已知值；缺项保留 null 并逐项统计 missing records。reported_total_accounted_wall_seconds 是另一项原样记录的总体计数，不能再加进父项和；全部父项已知时，二者差额另列 unclassified_reported_wall_seconds。training_teacher_forward_seconds 嵌套在 training 内，validation teacher/KL 算术时间嵌套在 validation 内，全部只作子成本诊断，不再次累加。旧记录缺少 setup 或 teacher 计时不会被伪造为精确零。

preparation_costs.csv 对每个真实生成池/统计 pass/bank selection 按 canonical artifact 只计一次。joint teacher NLL/features 是共享的一次准备，不能向每个选择方法重复加费；clustering 子计时已经包含在 cluster selection 内。410M 扩展的复制生成 bank 不新增生成/选择费，仅记录新 C4 selection。生成 pilot（包括已判无效的 EOS-stopping pilot）、2.8B memory smoke、独立统计成本诊断以及单独的 gradient probe 成本由显式 JSON pointer 白名单读取；不递归搜出所有 seconds 相加。衍生的 LR 评价 JSON 若只是训练 validation metrics 的复制，不能被当成新的推理费用。

loss_bounds.csv 单列 ENOSPC 丢弃生成的 83.31354104727507 秒观测下界。实际丢弃工作可能更多；exact_discarded_work_seconds 保持 null，且该下界不混进精确已记录成本合计。训练回滚、未记录的设置/失败尝试、尚在执行的操作也无法由当前累计 counter 完整恢复，不作补值。因此，本清单是已观察物理运行和已记录路径的成本清单，不能冒充所有机器实际消耗的精确总账。

所有输入保留 canonical 路径、观测字节数和 SHA；事件文件 hash 对应当次观察到的字节，未来追加不会改变这份快照所指的内容。JSON pointer、registry 引用和 selected counter 的来源/行号可回查每项数字。源 JSON 中已经记载的池 artifact SHA 只作来源引用，本工具不重散列大 tensor 文件。

各 run 的 wall 相加并非研究经过时长，也并非纯 GPU compute time；多 GPU 并行执行会重叠。现有 scripts/summarize_resources.py 的结果仅由 telemetry_reference 链接和散列，不重新积分：其中利用率积分是抽样活动代理、能耗是已覆盖时段的 GPU 能耗，不是逐 run 归因或全系统能耗，不与 wall counter 相加。

现在也支持显式 v2 evaluation manifests 与 execution attestations。当前只读快照的来源表为 `configs/cost_inventory_sources_with_evaluations_v1.json`，输出在 `results/cost_inventory_with_evaluations_v2`；原始来源表与旧快照保留。新的来源表同时补入已冻结补充 B、extended LR/lambda 和当前 C active registries，不把未完成的计划伪装为已完成。

```json
{
  "evaluation_manifests": [{
    "path": "docs/PHASE_manifest.json",
    "sha256": "预先固定的完整manifest SHA256",
    "category": "primary",
    "scheduler_state": "logs/supplemental_job_state.json",
    "verify_output_hashes": true,
    "execution_attestations": {
      "JOB_ID": {"path": "results/OUTPUT_execution.json", "sha256": "可选的已知凭证SHA"}
    }
  }]
}
```

`execution_attestations` 可以省略，此时从清单中的 output 推导规范路径。对于 reuse job，job.output 指向旧 canonical 结果；新 wrapper 自己的执行凭证存放在新 materialized logical endpoint 旁。因此工具从其第一条逻辑 alias 取一次自身 verification 计时，同时用 `inference_origin` 追溯原 canonical identity。不会把旧 canonical 的输出凭证误当新 job，也不会把多个 alias 继承的 verification 重复加费。`verify_output_hashes=true` 只流式散列评分文件字节，完全不反序列化评分结果。replay-fit 的该开关是在15项全部 completed/rc0 后才启用。

`evaluation_executions.csv` 按 `(manifest SHA256, inference job ID)` 去重实际 wrapper 记录；`evaluation_canonical_inferences.csv` 将跨 phase reuse 解析到原身份，canonical 尚未显式纳入输入时如实标记 external/unregistered。`evaluation_references.csv` 保留 baseline/每个 logical endpoint 和完整 model-state 等价来源；逻辑 alias 不产生新模型前向。相同清单重复列入不增加推理费；冲突的分类单列 classification_conflict。`evaluation_manifest_status.csv` 保留缺失来源，`evaluation_category_totals.csv` 汇总已知值及缺项数。

执行凭证中的 `verification_wall_seconds` 是 SHA 与 manifest/input 校验的合计，不能再拆称纯 SHA 时间；独立 environment preflight 未插桩，保持 null。`scorer_subprocess_wall_seconds` 单列。调度 elapsed 与二者差额作为未归属 residual，仅说明可能包含 environment/preflight、dispatch、alias 工作或 polling；不称纯 GPU 或单独的精确 preflight 耗时，也不再次加入计时和。别名复制耗时未单独插桩，保持 unknown，零额外 forward 不等于零 CPU 工作。

输出内的 wall/teacher/KL 等计时全部不读取、不相加。category_totals 的新增 combined 字段只加训练四个父计时、已明确可加的准备成本、唯一执行的 verification+scorer wall；遥测、调度 elapsed 和别名继承计时不加。失败且无凭证的 job 保留 scheduler 状态、returncode 和已观测 elapsed，scorer 成本保持 null；成功后 alias 材料化失败而留下 canonical 凭证时保留已知 scorer 成本。该推理部分仍只是 last-attested-path accounting，无法恢复被覆盖重试、失败前未插桩或丢失的工作，不能冒充完整物理尝试总账。

合成 CPU 测试使用不可解析为 JSON 的 PRIVATE_SCORE 字节，覆盖重复 baseline、同权重 alias、跨 phase prior reuse、缺失/失败、源清单或结果变更，以及 replay 15项齐备前不读取结果字节。测试不会加载任何真实模型或评分。

账本覆盖边界现另存为 `coverage.csv`（JSON 同名字段）。最新来源表为 `configs/cost_inventory_sources_with_evaluations_v2.json`、只读快照 `results/cost_inventory_with_evaluations_v3`；先前 v1/v2 快照均保留。该表把方法生成/统计/训练/评估的已记录部分，与数据下载、环境安装、CPU数据处理、根报告绘图打包、共享盘发布和丢失工作分开；后几类没有完整结构化计时的保持 null，`unmeasured_cost_is_zero=false`，不能把它们视为0或声称所有24小时物理工作已测全。

可靠后处理 receipt 可在显式来源表的 `postprocessing_receipts` 声明 path、component、wall_pointer、status_pointer、expected_status、gpu_used_pointer、identity_pointer。只有状态匹配且非负有限的 wall 才登记已知时间；指向单一标量，不递归相加。按物理 receipt 身份去重复引用，不按相同输出内容推断两次实际工作相同。`postprocessing_costs.csv` 独立列出这些 CPU/IO wall，不加进方法比较 category_totals，也不当作 GPU 时间或并行研究 elapsed。

当前 `artifacts/assets/primary_weight_delivery_acceptance.json` 中已验收的原始 receipt 记录2053.5508109889925秒，涵盖 scratch 无损权重归档及逐字节 roundtrip/成员验证，`GPU_used=false`。它不是共享盘发布完成或完整transfer耗时的证明；这部分保持单独 unknown/in-progress，直到有可靠receipt。成本模块不再运行归档或散列25GB TAR，只记录小型验收JSON的来源 SHA 和指定计时字段。

整项24小时研究另以工程合同 deadline/timewindow 和现有 sampled GPU telemetry 的时间覆盖描述。各方法 wall 是可比较的已记录分项，所有并行 wall 相加既不是研究 elapsed，也不是 GPU compute hours。实验失败/回滚、未知预处理和未插桩后处理仍构成账本缺口；metadata 明确 `whole_study_cost_completely_instrumented=false`。
