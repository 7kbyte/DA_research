## 来源与完整性

A/B 使用已冻结、完整 READY 的 NLL 身份 manifest，只读身份元数据。A93、B60 的 run/actual run/原 checkpoint SHA 已与独立 scope 完全相符。C63 的 run/model 范围也一致，但源码在每模型真正完整 READY、全阶段 audit 和 best 等价 proof 到齐前不读其 best checkpoint。READY 标记必须绑定当前 manifest 字节；单纯出现临时 manifest 不算就绪。

每个源训练 job 必须 rc0、completed、无 `stop_requested_at` 字段，实际 argv 与冻结 definition 相同；config、registry、训练输入、执行 policy 和完整 horizon 均核验。合法评价 append 不会让整个 mutable master queue SHA 变成长期门禁。输入 SHA 冲突直接拒绝，catalog 不能覆盖原冻结哈希。

真实操作时，完整读取源 checkpoint SHA 并匹配冻结身份，绑定 path 与打开 fd 的稳定五项 stat；检查全部 FP32 model state、实际 counters、验证选中 best 元数据。每个新权重都 encode→decode→与原 checkpoint 全 uint8 逐 tensor 比较；非权重元数据另完整往返。成功 draft 和所有原件始终保留。resume 同时绑定本包、本 scope、完整 cohort、manifest 和各来源，不能拿另一包的合法 completion 顶替。

组包前要求完整逻辑范围；校验所有成员、完整 TAR、实际字节上限并 fsync。任何单阶段失败都不称完整包。发布由 ROOT 使用既有 publisher 单独执行，本导出器没有自动发布功能，也不消费预留文件。

首例成功后再次 max1 不会取得第二个样例。批量必须传 `--resource-review PATH --resource-review-sha256 SHA --max-new-weights N`；外部 ROOT 收据须绑定本源码、本 scope、已完成本包样例的 SHA、资源与保守时间估计。初始批许可仅 A/B。C 每模型在实际 READY 后须 ROOT 另行允许首例，再独立审实际资源/时间后才可批量；A/B 许可不授权后继 C 的第一个样例。

批量收据的 `status=accepted_cpu_resource_samples`、`authorized_by=root`；字段包括 `scope_sha256`、`exporter_sha256`、`approved_packages`、`protected_finish_deadline_utc=2026-11-07T02:56:32Z`。每个 `package_plans[包名]` 含 `actual_sample_record:{path,sha256}`、`estimated_seconds_per_unique`、`assembly_allowance_seconds`、`ROOT_publication_allowance_seconds` 和至少120秒的 `finish_margin_seconds`。本准备任务不生成 ROOT true 许可。

两道保守时间门槛在阶段开始、每次新操作前及组包前检查：`now + 剩余 unique×单项估计 + assembly allowance` 必须严格早于 **02:00 UTC**，作为预计 publication start；再加 publication allowance 与 margin 必须不晚于 **02:56:32 UTC**。实际到02:00不再开始新操作，已开始操作可完成；这些估计不构成硬运行时间保证，ROOT 仍可采用更严格许可。publication 是独立新操作，也遵守02:00开工边界。

## CPU、I/O 与成本边界

固定额外锁为 `/tmp/grad-research-20261106/delivery/.additional_endpoint_slot{1,2}.lock`，与原 C final 锁不同；输出 namespace 改名不能绕开两 slot 限制。每 worker 两 CPU 线程、CVD 空。两个新增 worker 加现有 C final，最多三个编码 worker。只读同一不可变源文件安全；文件缓存争用可能降低吞吐。ROOT 提供的容器限制约960 GiB，当前大多为可回收 clean file cache；不能将宿主机2 TB空闲量视作容器自由内存。此前2.8B RSS 约22.755 GB仅作代理，首例要实测累计 RSS 和 cgroup events。

v4 preflight 实测10.175718秒墙钟、9.695837秒进程 CPU（函数入口至输出前，不含 Python import/工程工作）。native base 完整 SHA 共读取9,598,141,888返回文件字节：410M 因两个独立来源核验读两次，1B/2.8B各一次；这不是物理磁盘流量。原训练 checkpoint payload 读取0。已持久大 TAR 只沿用历史全包验收加当前 stat/owner/inode，并新核小 manifest，未重新全读大 TAR。

真实运行的每个 endpoint 是独立 wall/CPU 父项，encode/decode/逐字节验证是嵌套子项，不重复相加；assembly 独立。启动输入重哈希和 resume 已完成 TAR 重哈希另有 operation 收据；daemon elapsed 含等待，仅作上下文。本平台没有 `/usr/bin/time`，实际启动可用 Bash 内置 `time`，或外层 Python `Popen` 配合 `resource.getrusage(RUSAGE_CHILDREN)`，记录整个进程 user/sys/wall。这样覆盖 imports、启动验证与提交收据；该父项不能与子阶段再次相加。
