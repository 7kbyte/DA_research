本补充诊断只度量 replay bank 准备计算，不改变冻结的 generation、selection、evaluation 或 training 模块。根代理于 2026-11-06 授权 GPU1 短窗口。固定 Pythia410M 初始 teacher、pool_seed11 全部1957×512 chunks、batch16、FP32 weights/BF16 autocast，执行冻结 strict/auto policy（含 cuDNN SDP=True、TF32 matmul/cuDNN=True、cuDNN deterministic=True、benchmark=False、CUBLAS=:4096:8）。

分别运行 NLL-only（冻结extract_teacher_statistics的include_features=False）、feature-only（直接gpt_neox base transformer的最后归一化hidden，不调用LM head、不保存中间层history）、joint（原冻结extract_teacher_statistics）三种路径。共同使用因果有效context位置0:L-2和邻接attention mask。每种路径先warmup一个batch，随后三次完整测量；模式顺序固定NLL、feature、joint并记录。模式之间清理allocator cache，模式内保留warmup cache。每次记录whole-pass wall、CUDA event stream elapsed和allocated/reserved峰值（含FP32模型）；CUDA event span包含host gaps，不冒充GPU active kernel时间。模型加载、warmup单独记录，输入pool/stats/script都有SHA。

每次重算逐元素比较冻结teacher_nll/features/counts，报告exact equality及max/mean absolute和relative L2误差，不通过宽松容差隐藏差异。旧stats来自更早forward policy，故若当前strict policy引入误差应如实报告。CPU genuine tiny GPTNeoX测试验证feature-only完全绕过LM head，且causal mask/pooling与原joint完全一致，NLL-only也等于joint。

随机与exact dedup random无需teacher stats。独立部署M计NLL-only加selection；独立部署C计feature-only加clustering/selection。本次研究资产共用一次joint pass，实际共享准备成本只计一次，不能再向每个方法重复加joint费用。该诊断不测量retention，也不把feature几何coverage当retention指标。
