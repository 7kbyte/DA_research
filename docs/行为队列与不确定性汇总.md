该工作流只从完整、active、formal 的显式 registry 冻结行为评价。资格要求包括：protocol_status 的 active registry authority、每个 run completed、达到规定的 target exposure、科学配置与 summary 匹配、strict SDPA，以及单一模型/revision/推理配置。device、output_dir、resume_from、max_steps、deadline 和保存频率等合法 operational 差异不改变科学资格。旧 provisional registry、未完成 summary、不同模型混批均拒绝。先全表资格检查，再 streaming SHA，避免未完成时先散列大量 checkpoint。

冻结命令示例（需要全部 formal run 完成后再执行；当前不启动 GPU）：

```bash
python scripts/make_behavioral_queue.py \
  --registry configs/formal_deterministic_registry.json \
  --model-tag pythia-410m --output-root results/behavioral \
  --batch-size 16 --max-length 2048 --checkpoints final best \
  --queue configs/behavioral_pythia-410m_queue.json \
  --manifest docs/behavioral_pythia-410m_manifest.json
```

每个 modeltag 的输出放在 OUTPUT_ROOT/MODELTAG。初始模型只生成一个 job，所有 final/best 都显式依赖它。final exposure 来自完成 counters；best 来自唯一匹配的 target-validation trajectory，不能用 final budget 冒充 best 实际训练量。manifest 记录 phase、step、target/replay exposure、checkpoint/config/summary SHA、原始模型权重/config/tokenizer SHA，以及数据和官方 harness 源码 SHA。acc_norm 为主、acc 为辅；两套 CC/CW/WC/WW 和逐题 choice logprobs 都保留。

相同模型的另一个 formal registry（例如 410M 扩展训练）可用 `--initial-manifest 已冻结的原始manifest.json` 复用同一 baseline 计划。模型、revision、行为 batch/context、数据及 scorer SHA 必须完全相同；不支持链式别名。新 queue 不重复创建 initial job，而保留对原始 initial job ID 的显式 DAG 依赖，因此 root 合并两份 DAG 后只运行一次 initial。不同模型必须单独冻结队列和 manifest，禁止混批。

队列不直接调用 scorer，而调用 `run_frozen_behavioral.py`。该包装器执行前复核 manifest、自身/scorer/数据/初始权重和该 checkpoint 的 SHA，仅允许 scheduler 覆盖 device 序号。完成后保存 `*_execution.json`，绑定 manifest、job、checkpoint SHA 及全部结果 SHA；队列的成功 outputs 包含该凭证。`--verify-only` 只进行 CPU 完整性检查，不加载模型。实际推理仍须 root 在统一补充协议冻结后调度，生成 queue 不表示自动运行。

评价结束后，CPU 汇总命令为：

```bash
python scripts/analyze_behavioral_results.py \
  --manifest docs/behavioral_pythia-410m_manifest.json \
  --output results/analysis/behavioral_pythia-410m
```

汇总拒绝不完整 split、smoke、模型/checkpoint/数据/batch/context 不匹配、缺少执行凭证、结果 SHA 改变，以及用 token 数冒充字符归一的 stored choices。它导出 endpoints.csv、seed_aggregates.csv、paired_seed_differences.csv、paired_seed_aggregates.csv 和 analysis_manifest.json。所有读取都显式绑定 manifest，不 glob 旧结果，不反序列化 checkpoint 权重，也不执行模型推理。

不确定性政策在看到真实行为结果前固定：每个 checkpoint、task、score 单独给 95% Wilson accuracy 区间；相对初始模型的 accuracy delta 给 5000 次 paired-example percentile bootstrap，随机种子 20261106。因 correctness 只有四种成对状态，对 CC/CW/WC/WW 的 multinomial 重抽样与逐题 iid 成对 bootstrap 完全等价，保持同一题 before/after 配对，不做独立重抽样。两套 normalization 独立计算。Wilson 的二项模型与这里的 paired-example bootstrap 都依赖题目可按独立/可交换单位处理的假设。HellaSwag 等数据可能包含同源活动、原视频或上下文的相关题目；当前没有按这些来源分组重采样，也未校正群内相关性。因此，题目区间只作为给定已训练 checkpoint(s) 和当前题目重采样假设的条件描述，不能自动称为目标总体表现或训练随机性的置信区间。固定 benchmark 上的准确率本身由整数答对数精确确定。报告主表保留 seeds 11/22/33 的三个个体值及 mean/sample SD(ddof=1)，题目区间仅放补充描述，不能替代或放大训练重复数。

训练重复单位始终是 seed。每个训练 cell 先分别计算 seed 结果，再给 mean 和 sample SD(ddof=1)；单 seed 的 SD 未定义。预先指定的比较为 M−B4、C−B4、B2−B1、B4−B3、D−B4；先匹配 seed、replay ratio、lambda、LR、checkpoint kind、task 和 score 后作差，再汇总 mean/SD。不同 budget 不配对，final 和 best 不混合；best 两侧真实曝光量同时导出。不把数千个题目当成数千次独立训练，也不根据行为得分改变 prompt、checkpoint、主要指标或比较集合。

CPU 审阅后的计数与小数追溯规则：每个 task/score 的 N=CC+CW+WC+WW，初始准确率=(CC+CW)/N，当前准确率=(CC+WC)/N，accuracy delta=(WC−CW)/N；遗忘率=CW/(CC+CW)，获得率=WC/(WC+WW)，分母为零时保留 undefined，不填零。CSV 保留 N、四个整数计数及每个 seed 的值，所有准确率和差值均可由这些整数复算；逐题 choice logprobs、字符长度、gold、fingerprint 和 SHA 可回查判定依据。Wilson 使用 z=1.959963984540054，bootstrap 的95%端点使用 NumPy quantile 的默认 linear 插值，显示值不先舍入再参与计算。

每个 bootstrap stream 的 seed 明确为 `(20261106 + int(SHA256(job_id + "|" + task + "|" + metric)[:8], 16)) mod 2**32`，端点 CSV 导出实际派生 seed。四类抽样顺序固定 CC/CW/WC/WW；同一题的 before/after 始终共同抽样。不同 job/task/score 使用确定的独立 Monte Carlo stream，不能用两份边际区间相减或根据区间重叠宣称模型差异区间；目前模型间比较使用匹配训练 seed 后的差值和 SD。若 final/best 恰好有相同预测而 interval 受不同 stream 的 Monte Carlo 抽样影响，应区分区间抽样误差与精确相同的点估计。

曝光与成本严格按不同来源追溯：final 的 step/target/replay exposure 来自完成 counters；best 的这三项来自唯一匹配的 validation point，不能替换成最终预算。行为 endpoints CSV 和 paired-seed CSV 只描述相应 checkpoint 的结果及真实曝光，不把 exposure 当成本。完整训练实际成本仍由该 run 的已完成 summary 中 counters/timing 追溯，并以 run_id 计一次；即便选出较早 best checkpoint，也不能按 best/final token 比例缩减已实际完成的训练费用。final 与 best 是同一次完整训练的两个评价端点，不能把训练总成本加两遍。SHA 验证开销和行为评价子进程开销由各自 *_execution.json 分列；它们不是训练时间，主分析的 shared generation/joint-preparation 成本也不随两个 checkpoint 重复计费。
