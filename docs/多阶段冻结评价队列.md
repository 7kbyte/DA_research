v2 工具只做 CPU 工程，不改冻结 scoring/execution core、不启动模型。旧单 registry CLI/API 保留兼容；补充 A/B/extended 应使用 `--phase-spec` 显式来源，不改写 phase 冒充 primary。

phase-spec 顶层为 `schema_version:2, science_frozen:true, phases:[...]`。每个 phase 必须包含下列字段：

- `name`、`role`（primary/supplement_A/supplement_B/extended）、`expected_phase`、`science_frozen:true`、`model_tag`、`model:{path,revision}`。
- `registry:{path,sha256}`、`protocol:{path,sha256}`、`protocol_expect:{...}`。expect 是应核验的实际协议字段子集，例如 data_version、selected LR/lambda、科学冻结状态。一个 registry 内拒绝不同模型/revision。
- `data_family` 为 main_v3 或 extended_v1；`training_data:{path,sha256}`，以及各含 target/c4/wikitext 三个 `{path,sha256}` 的 `validation_data`、`test_data`。main_v3 必须匹配主训练/evaluation_v3；extended_v1 必须匹配 data_extended。cfg、registry、protocol 的路径/SHA 互相核验。
- row.config_sha256，或 phase.config_sha256 的 run_id→hash 映射。primary 从原冻结 snapshot 取值，B 从 runtime activation 取值，不用当前散列冒充原冻结证明。`source_proof_files:{path:sha}` 可绑定 snapshot、audit、选择记录、preparation/activation/index。
- phase.checkpoints 可指定 final/best。子集必须 `selection:{record:{path,sha256},record_expect:{...},run_ids_field:"...",include_run_ids:[...]}`；所选 IDs 与冻结 validation-only 选择记录相同。

所有选中 row 都须完成 prescribed target/replay prediction tokens；summary 科学配置须匹配，strict SDPA 须匹配。只忽略已列出的 device/output_dir/resume/deadline/保存频率等 operational 差异。alias 须 execution_kind=alias、alias_of、counted_as_new_training=false；cfg.run_label 必须仍等于 actual_run_id。B 分开记录 training_seed/generation_seed/selection_seed，不把选库随机性当训练重复。

每个 endpoint 保留真实 phase/role、model/data family、kind、step 及实际 target/replay exposure。best 必须匹配唯一 validation point 及首次最小 target-validation NLL。full_training_committed_path 保存完整训练 counters/父计时，不能按 best 曝光缩减完整训练成本，也不能把两个 endpoint 重复计费。

baseline identity 绑定 model/revision、初始权重/tokenizer、heldout/task/scorer SHA 及实际 precision/backend/strict/TF32/四个 SDP 开关/batch/context。NLL 使用 run 的 evaluation_batch_size，同模型不同 batch 需要匹配 baseline；主 v3 与 extended heldout 分开。行为 spec 顶层须 `behavior:{data_root,batch_size,max_length,data_manifest_sha256,harness_manifest_sha256}`，phase 可单独覆盖 behavior.batch_size/max_length。相同模型及实际行为策略可以跨主/扩展训练共享 baseline，因为任务题目相同；训练 microbatch 不参与行为 identity。

第一次真实评分前补充冻结：执行 policy 必须先逐项核对每个 completed summary.provenance 的实际 precision、四个 SDP 开关、strict/warn_only、TF32/cuDNN/CUBLAS、FP32 model/required-teacher dtype 与 cfg 期望，不用当前环境补缺失训练证据。训练 provenance.gpu 映射为 gpu_name；实际 torch_version、cuda_version、gpu_name 进入 baseline identity。包装器在真实评分前检查所分配 worker 的三项环境，并在结果中再次逐项核对。verify-only 仍只 CPU 散列，不查询 CUDA。旧 primary_evaluation_v2 清单保留但已 superseded，不能启动；修订版使用 primary_evaluation_v2_execution_matched 前缀。

整 checkpoint SHA 相同直接复用。不同文件只有完整 model_state 等价证据才复用，不能按 bank、loss 或 step 猜测。`model_equivalence_proofs:[{path,sha256}]` 的文件 schema 为 version1、algorithm=`sha256_sorted_key_dtype_shape_contiguous_uint8_v1`、algorithm_source={path,sha256}、comparisons=[{bitwise_model_state_equal:true,left:{checkpoint,checkpoint_sha256,model_state_fingerprint:{sha256_model_state,state_elements}},right:{...}}]。核验两边当前文件 SHA、完整 key/shape/dtype/bytes fingerprint。仍只在相同 model/tokenizer/data/actual policy 组内复用，source_model_equivalence 记录来源；不同物理训练身份与成本保留。

生成命令（不启动评分）：

```bash
python scripts/make_evaluation_queue.py --phase-spec configs/frozen_nll_phase_spec.json \
  --output-root results/test_v2 --queue configs/test_v2_queue.json --manifest docs/test_v2_manifest.json
python scripts/make_behavioral_queue.py --phase-spec configs/frozen_behavior_phase_spec.json \
  --output-root results/behavior_v2 --queue configs/behavior_v2_queue.json --manifest docs/behavior_v2_manifest.json
```

主36专用 CPU 冻结命令 `python scripts/prepare_primary_evaluation.py --output-prefix 一个未使用的新前缀` 要求最终 audit passed，并从原 input snapshot 提取 config/data/protocol SHA，同时消费 final/best D/B4 证明。当前修订产物前缀为 `primary_evaluation_v2_execution_matched`。工具输出独立 phase spec、NLL/behavior endpoint manifest、两份平面 queue 与 preparation evidence；checkpoint streaming SHA 在两次 build 之间缓存，未反序列化模型。

结果按 OUTPUT_ROOT/model_tag/phase_name/run_id/{final,best}.json，baseline 按完整 identity 存在 model_tag/baselines。相同推理的 logical aliases 只复制或硬链接结果，记录 canonical inference、各自 checkpoint SHA 和零额外 model forward。alias attestation 的额外 inference wall=0，原结果内部 timing 属于 canonical，不得再次相加。

队列是 master 所需的平面 list。每 job 只调用 run_frozen_evaluation.py 一个 single-GPU child，继承外层 CUDA_VISIBLE_DEVICES、固定 cuda:0，无内部 scheduler。包装器执行前重验 manifest/inputs SHA，执行后核验实际 policy 与完整 split，再写 *_execution.json，分列 CPU 校验 wall、scorer subprocess wall、结果 SHA。wall 不是纯 GPU 时间。`--verify-only` 只 CPU 校验；真实 baseline 的完成证明在执行时检查。

后续 spec 可用 prior_plans=[{path,sha256}] 引用原始 v2 计划，复用 initial/完整 state 相同的已排推理，不支持 alias 链。新 queue 对旧 job 保留显式依赖，须追加到保留旧定义的同一个 master DAG。root 冻结授权后追加示例：

```bash
python scripts/manage_supplemental_queue.py append \
  --master-queue configs/supplemental_v1_queue.json \
  --phase-index configs/supplemental_v1_registry_index.json \
  --phase frozen_eval_PHASE --phase-queue configs/test_PHASE_queue.json \
  --phase-registry docs/test_PHASE_manifest.json
```

manifest.workload 分列 logical endpoints、physical training、实际 adapted/initial forward、reuse materialization、每 inference group 的题目/choices/tokens/策略。成本为 Σ_g(N_initial×同策略实测秒数+N_adapted×同策略实测秒数)，CPU SHA/复制另计。expected_seconds 是调度 allowance，明确不是实测成本；teacher 子计时不能重复加父 wall。

准备 queue 不等于授权推理。若提前运行已冻结 phase，应先固定后续科学方法/grid/validation-only 选参规则，结果封存；调度只读退出状态和耗时，不根据先到 test/行为分数改变后续科学或预算决策。当前工具准备没有执行任何真实评分。

v2 行为结果使用独立 CPU 汇总器，避免旧单 phase collector 混合主/扩展/补充 cell：

```bash
python scripts/analyze_behavioral_plan.py --manifest docs/primary_evaluation_v2_execution_matched_behavior_manifest.json \
  --output results/analysis/primary_behavior_v2
```

它复核 baseline/每 logical endpoint 的执行凭证、结果 SHA、完整题目、原始 choice logprobs 与字符归一判定，并按 role/phase_name/data_family/model_tag/baseline_group 分层，分开 final/best，再配对训练 seed。导出 endpoints/seed aggregates/paired-seed CSV 和来源 metadata。保留四个整数转移计数、实际曝光和确定派生 bootstrap seed（SHA256(logical_record_id|task|metric)前8位加20261106 mod2^32）；题目重采样只有给定 checkpoint 的条件解释。相同预测的不同 logical endpoints 可能有不同 Monte Carlo 区间抽样误差，不能把它当模型差异。selection_seed 不是训练 seed，带 selection_seed 的 endpoint 不进入跨训练seed的 SD。完整训练成本由SHA绑定summary按physical run另计，不放进endpoint曝光或重复计费。
