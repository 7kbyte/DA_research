每个 extended 410M / 1B 阶段的24项真实训练全部成功退出后，独立 CPU watcher 发布该模型的权重等价证据。2.8B 没有 D 组，沿用其完整15项训练门禁。本流程不修改全63项综合审计，也不修改训练队列、科学源码或任何已冻结配置。

启动命令如下；已有 watcher 运行时不要再启动第二份。程序通过文件锁拒绝重复实例。

```bash
CUDA_VISIBLE_DEVICES= OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  python scripts/watch_extended_phase_equivalence.py
```

watcher 核对主队列中的24项 job 与各自冻结 phase queue 完全相同，并要求 scheduler definition SHA 相同、status=completed、returncode=0、所有声明输出存在。完整门禁后调用现有 `audit_extended_runs.audit_phase` 检查输入/配置/代码 SHA、token 预算、目标流、LR 日程、验证轨迹、实际执行政策、checkpoint 和成本记账。仅 D/B4 轨迹是否逐值相同单独作为数值诊断报告；其他源状态问题阻止发布完成凭证。原始审计结果完整保留，不覆盖或隐藏差异。

随后按 final、best 顺序，逐 seed 11/22/33 顺序加载 B4/D checkpoint。PyTorch intra/inter-op 均为2线程，不启动 GPU。完整 model_state 指纹直接复用 `make_model_equivalence_proofs.checkpoint_identity` 与 `audit_formal_runs.model_fingerprint`：对每个排序后的 key、dtype、shape 及全部 contiguous uint8 字节计算 SHA256，同时绑定 checkpoint 文件本身的 SHA。训练标签、optimizer 或序列化信息可以不同，不能据此推断模型权重不同或相同。

best 端点必须是 target 验证轨迹的首次最低 NLL 选点，并同时核对 summary、checkpoint 内 selection/config/counters 与实际 exposure；final 必须与完整训练计数及保存的验证轨迹一致。相同步数、相同银行或相同验证分数均不能替代完整权重指纹。每个模型完整核算六对（3 seed × final/best），不会只检查其中一个端点。

结果位于 `results/extended_phase_equivalence/<configuration_prefix>/`：

- `audit.json`：源状态审计，包含24项 scheduler 记录、实际完成数、输入 snapshot/registry SHA、原始逐 run 审计与数值诊断。
- `final_model_equivalence_proofs.json`、`best_model_equivalence_proofs.json`：各三对真实 checkpoint，记录文件 SHA、完整 model_state 指纹、summary/config SHA、实际选点和 exposure。
- `completion.json`：最后原子发布，绑定 audit、两份 proof、输入 authority 与全部 summary/config/events SHA。评价准备必须等待此文件及全部绑定 SHA 校验通过。

`status=passed` 表示核算与源状态验证完整完成；是否权重相等必须读取每对 `bitwise_model_state_equal` 和独立的 `all_pairs_bitwise_equal`。false 对原样保留、明确报告，并独立执行评价。既有 evaluator 只消费 true 对作为等价证据。不相等不会被强行合并，源状态异常不会产生可用于 READY 的完成凭证。所有源输入在发布完成凭证前重新核对 SHA；重启读取既有凭证时也重新核对 checkpoint 文件 SHA，不覆盖已发布证据。

CPU watcher 进度为 `logs/extended_phase_equivalence_watch.json`，启动记录为 `logs/extended_phase_equivalence_watch_launch.json`。任何源/状态失败写入进度并退出，需人工查看；不会启动训练、推理、评分或第二个 GPU scheduler，也不读取 test/behavior 分数。
