# CPU 预哈希与评价交接（运营修订 v5）

本修订仅将已完成 checkpoint 的字节校验提前到训练期间；科学条件、完整 phase 门禁、validation-only 选参、评价范围和冻结评分器不变。v4 准备器源码保留，v5 使用其原 `pass_once` / `build` API，显式传入兼容的缓存对象，不修改模块全局或评分 worker。原 v4 在 0/9 READY 时停止，原目录和快照作为历史保留。

## 当前规范入口

- Catalog：`configs/supplemental_evaluation_preparation_v5.json`，保持原九个 plan ID 和 READY/manifest/queue schema。
- CPU 包装器：`scripts/prepare_supplemental_evaluations_v5.py`。
- 全文件校验凭证：`scripts/stat_bound_digest_cache.py`，工作目录 `artifacts/evaluation_digest_cache_v1`。
- 准备结果：`artifacts/evaluation_ready_v5/ready_index.json`；运行记录及可绑定的不可变缓存 snapshot 见同目录 `cache_progress.json`。
- 最终交接仍由 `scripts/handoff_evaluation.py` 的 `prepare` / `start` 操作显式授权，预哈希器本身不启动 GPU 或 scheduler。

## 凭证如何取得与复用

逐 run 的前置条件为：冻结 registry/config SHA 与 scheduler job 定义一致、实际 argv 匹配、scheduler 状态 completed 且 rc0、未请求停止、声明输出存在、summary 完整且配置及 target/replay prediction-token 预算匹配。只顺序读取 opaque checkpoint 文件，不反序列化权重，不读取 test/behavior 评分内容。final 和 best 都单独核查路径；最终科学资格仍由原完整 phase gate 及 C 等价证明 gate 决定。

一次可复用凭证必须确实将文件从已打开 fd 读到 EOF，记录实际 SHA256、读入字节数、reader 源码 SHA、开始/结束时间、完整来源，以及 canonical path 的 dev/ino/size/mtime_ns/ctime_ns。打开前路径 stat、fd 前后 stat、结束路径 stat 及 canonical 路径必须一致；目录及 JSON 原子替换前后的 fsync 完成后才引用该凭证。

缓存命中仅意味着当前五项 stat 与历史完整实读凭证一致；不会声称此次又读了文件字节。路径缺失失败，stat 改变则失效并重新全读，错误的 expected SHA 或损坏凭证均拒绝。已确认完成 checkpoint 若内容改变则报错。跨进程读取只接受显式 SHA 绑定的 index snapshot，逐 receipt SHA 仍须核查。该优化依赖本地文件系统的上述身份与时间戳，不能当作不受本机文件所有者约束的密码学认证。

## 最终 handoff 的可选配置

`handoff_draft.json` 仍是 `example_only=true` 的草稿。root 完成范围及退出门禁审查后，可在新、明确授权的 spec 中加入：

```json
{"digest_cache": {"path": "<cache_progress 中的 immutable snapshot path>", "sha256": "<该 snapshot SHA256>"}}
```

未提供此项时，prepare/start 保持原有逐输入 fresh SHA 行为。提供后，prepare/start 分别加载同一 SHA 绑定的 snapshot，核查每个选中输入的当前身份及 expected SHA；未命中的文件必须全读。默认不能用 `verify_inputs=False` 或空 callback 跳过校验。两次收据分别列出 `cache_hits`、`full_reads`、`full_read_bytes`、`invalidations`，其中范围为选中推理输入；小 manifest/queue 及已完成输出的 attestation 校验仍独立 fresh 执行。

真实 `run_frozen_evaluation.py` 在每个 GPU 任务开始前仍完整实读其冻结输入 SHA；本缓存不进入 worker。旧 master 及 children 全退出、旧锁释放、同 ID 定义一致、baseline 依赖闭包、完整已完成输出及至少 30 分钟收尾余量等原有 handoff 门禁均保留。禁止训练 job 进入评价后继队列。

## 关键路径量级

原计划中 2.8B final+best 共约 666.06 GB；v4 首次要等 15 run 全完成才开始哈希，若持续 1/0.5/0.25 GB/s，需要约 11.1/22.2/44.4 分钟。全部主及补充所需 checkpoint union 估计约 2.261 TB；原 prepare/start 两遍校验约 75.4 分钟（1 GB/s）或 150.7 分钟（0.5 GB/s）。这些是根据已存在 checkpoint 大小与既有 verification 时间作的保守运营估算，不是 GPU 性能或科学结果。

v5 将各完成 run 的哈希分散到训练期间；最终仍要检查当前 stat、补读未覆盖输入和运行各项科学门禁，因此不会宣称交接成本为零。新单次实读 smoke 对一份主 final checkpoint 耗时约 4.47 秒；精确读取字节数及其他小输入校验成本见 v5 smoke 及执行收据，不将缓存命中记为当次 I/O。
