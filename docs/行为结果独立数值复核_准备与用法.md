# 行为结果独立数值复核：准备与用法

本工具仅审阅已经 ROOT 明确解封、完整成功的行为分析。当前验收只使用临时合成数据；没有打开任何真实行为分数、逐题预测，也没有运行原 check/analyze、创建 authority 或首读 journal。原 scorer、guard、collector、统计模块和真实计划保持原字节。

入口为 [review_behavioral_results.py](../scripts/review_behavioral_results.py)，测试为 [test_behavioral_independent_review.py](../tests/test_behavioral_independent_review.py)。已有 `analyze_behavioral_plan.py` 是原始 collector，`behavioral_analysis.py` 是其统计实现，原有测试验证这些实现；此前没有从原始逐题选项分数独立复算并与分析产物比对的 reviewer，因此增加这个独立入口。它不 import 原 collector/guard/scorer，也不调用原分析。

## 完整与授权门禁

CLI 必须显式提供原成功 `COMPLETE.json` 和完整 behavior manifest 的路径及 SHA。

- 主行为使用 `run_primary_behavior_analysis_v1.py` 成功 attempt 的 COMPLETE。审阅器核其 plan、ROOT true authority、完整 state proof、原 check、不可重置首读 journal 和原 analysis metadata。全部冻结 job 必须 completed、严格整数 rc0、无 stop/missing output，definition/实际 argv 一致。
- A/C 使用原 aux-v2/v3 完整模型 phase 的 COMPLETE。审阅器核完整 logical 数、physical/prior/reuse 闭包 readiness、ROOT authority、first-read、protocol；v3 另核 plan/manifest 绑定的 operational repair 和两版源 SHA。只有整个 phase final behavior 成功才可审阅，不支持 allow-partial。
- 两种入口均 fresh 校验原输出和逐题预测的完整 attestation 字节闭包、实际 matched initial 身份、每个逻辑端点的 checkpoint SHA/model identity、alias 的规范输出与零额外 forward 凭证、冻结的小源码 SHA。源/文件前后及结束时核 dev/ino/size/mtime/ctime。
- 原 guard COMPLETE 是其先前训练源、checkpoint、完整执行闭包校验的依据；reviewer 不重读 checkpoint。所有 `.pt/.bin/.safetensors`、压缩包及未知扩展名均拒读，不创建新评分任务。

COMPLETE/SHA 是调用方明确认可的来源，不是密码学签名。不能用手工伪造的成功标志替代真实 guard。工具不会给尚未解封的结果授权；未来真实调用仍须 ROOT 发出执行指令。

## 独立重算和固定覆盖

对 manifest 内全部方法、seed、final/best（主行为）或 final（A/C）、PiQA/HellaSwag、acc_norm/acc，均保留个体行；不按结果筛选。

1. 按 task/item_id 对齐完整问题，核 fingerprint/gold/choices。由每个 choice 的 logprob 及原始字符数独立 argmax，严格保留第一个并列最大项；主 acc_norm 与辅助 acc 分开核算。
2. 独立重算 accuracy、initial accuracy、CC/CW/WC/WW、correct→incorrect 条件率、incorrect→correct 条件率。用另一代数形式复核 Wilson 区间。
3. 用 Python `statistics.mean/stdev` 重算方法的三 seed 均值、sample SD（ddof=1），先同 seed 作差再求配对 SD。原主/C collector 的五个同 λ 方向是 M−B4、C−B4、B2−B1、B4−B3、D−B4；只核原表实际存在的 matched 条件，不创建不存在的 2.8B 方法组或新对照。
4. 重建冻结的 5000 次问题 bootstrap：相同派生 seed、CC/CW/WC/WW 类别顺序，但独立计数并用四状态线性对比和 percentile 计算。这样能逐数复核原有限 Monte Carlo 输出；随机数流本身并非独立重复。手算测试另穷举四题全部 4⁴ 个有序重采样，核分布均值、方差及分位数。容差固定为绝对 3×10⁻¹⁴，不为真实结果调整。
5. A 精确 join 原 validation-selected18 的 run IDs、实际 λ/seed/ratio/actual_run_id，独立复核六个既定策略对照和对应 right→left 问题 bootstrap。这是“各自验证选 λ 后的策略比较”，不是同 λ objective 因果比较；既有同 λ 表仍分别核验。

每行保留 actual_run_id、checkpoint、step、target/replay 实际曝光和 λ/LR；best/final 不合并为额外 seed。reviewer 不重算训练费用，也不把 best 的较少曝光当完整训练成本。成本读取须沿原 manifest 的 `full_training_committed_path`，按 actual_run 去重。

## A 原聚合 CSV 的标签边界

静态审阅发现冻结 `selected_policy_analysis._aggregate` 的分组键包含 task/metric，故 acc、acc_norm 分别以三 seed 汇总；随后 `metric=quantity` 覆盖了输出的 score 标签。原 `selected_policy_statistics.csv` 同一 task/对照的两行均标 `accuracy_left_minus_right`，不能仅按 metric 判断是哪套 score。逐 seed pairs、逐题 bootstrap 和 endpoints 的 metric 均保留正确身份；原行为分支也不基于该聚合表绘图。

不改原源码或 CSV。reviewer 将原聚合表作为完整数值行 multiset 核验；另从带 score 的同 seed pairs 输出 **`selected_policy_score_resolved_statistics.csv`**，分别用 `score=acc_norm/acc`、`quantity=accuracy_left_minus_right`，报告仅使用这个可追溯视图。另保留所选策略的逐 seed/问题区间独立表。合成测试专门构造两 score 均值不同的例子，复现原标签碰撞并拒绝合并；没有新增统计规则、推断或抽样。

## 解释与计时

Wilson 和 paired-example bootstrap 条件于这批固定 trained checkpoints，并按题目独立/可交换假设重采样。HellaSwag 同源 activity/context 等相关性未被校正；不能自动称为目标总体置信区间或训练随机性置信区间。主表保留全部三 seed 值、均值±sample SD；A 区间也不覆盖重新运行 validation λ 选择流程的不确定性。问题、final/best、D/B4 alias 均不增加训练重复数。

CLI 的外层父进程固定 CPU 两线程、CVD 空，完整记录 gate+SHA+独立数值检查 child 的 wall/user/sys；timer 为 `<新review目录>_whole_child_timing.json`，不与内部项相加。数据 bytes 是当前 fresh 读取并缓存一次的实际字节，不冒充 checkpoint 读取；工程/人工审图未计时部分不记为零。
