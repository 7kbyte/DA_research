# 扩展实验准备与复现

make_extended_experiments.py生成410M/1B/2.8B各自的LR、λ及formal配置。当前采用单个四GPUsupplemental master，训练与baseline evaluation均为单GPU child；阶段完成后由select_extended_phase.py在CPU上选参并生成下一阶段。calibrate_extended_experiments.py是旧的独立编排原型，不挂入本次master，也未执行GPU训练。

每model在seed101上按2M目标预测tokens运行B0 LR={1e-5,3e-5,1e-4}，按target validation NLL最低选共享LR，严格平手取更小值；再完整运行B1–B4×λ={.05,.5,1,5}，按四组平均S=Δtarget+.5(ΔC4+ΔWiki)最低选λ，严格平手取更小λ。保存独立模型基线、共享选择及源SHA。formal生成须提供同model、data_version=extended_v1的LR/λ选择记录。测试损失不参与选择。

目标是artifacts/data_extended/finemath_train.pt，评估必须用同目录匹配val/test，main v3不适用。银行来自对应model冻结教师pool及extended C4候选。410M generated银行复用来源见results/extended_pythia-410m_bank_provenance.json，不代称其他模型自生成。扩展目标包含主目标前缀，属于相关稳健性延伸，不能作为独立重复。

有效batch固定64chunks。410M/1B初始micro16 accum4；主36审计通过后的两个10step benchmark比较410M64×1和1B32×2，按docs/extended_batch_selection_protocol.json的吞吐与显存门槛选择。2.8B已测8×8通过且固定保留。evalbatch分别16、16、8。FP32 student/teacher权重、BF16 autocast及strict deterministic SDPA auto沿用主修订协议。

formal候选410M/1B各100M目标tokens、8组×3seed；2.8B为50M、B0/B1/B2/B4/M×3seed。同model所有方法共享完整目标暴露LR计划，不把主10M续训当作完整长计划。每153steps验证，即5003712目标预测tokens，最终预算点另验证。启动及预算由root依据吞吐决定，当前主strict36优先。

主36完成后的纯算时修订已一次性为2.8B选择25M完整15项，原50M候选保留，不做部分组。规则、50M/25M双预算SHA与选择见docs/2p8B训练时长预算修订.md和extended_2p8b_horizon_selection.json；命名空间增加h25m，显式--target-prediction-tokens 25000000，LR日程按25M完整horizon重建。2M短pilot规则不变，长程最优未保证。

当前后续编排使用独立v2命名空间extended_v2_<model>_m<micro>_<phase>，保存旧未启动候选。补充训练默认截止Nov7 00:00 UTC，可用--training-deadline显式调整；实际预算由root冻结。生成LR阶段时传--batch-selection-record（model及selected_microbatch匹配），共享LR/λ记录保存并强校验相同microbatch与accum，结果按model/m<micro>保存。改变批量后重新校准，避免继承旧微批量选参。2.8B维持已测通过的8×8。三模型独立v2校准均已完成并复算通过。

补充master初始110 jobs包含两个--one benchmark及A108；无需为测速另启GPU scheduler。依据吞吐/显存选择批量后，LR4jobs（一次initial+三点LR）和λ16jobs分阶段append到同一master。完整接口与B prepared-only激活规则见docs/补充单层调度说明.md。所有长期scheduler采用detached Popen(start_new_session=True)，child继承外层CUDA_VISIBLE_DEVICES并使用cuda:0。formal预算沿root授权及一次性2.8B时长修订冻结。

2026-11-06 06:30 UTC阶段冻结：410M micro64×1与1B micro32×2各24×100M，均选LR3e-5、λ.05；2.8B micro8×8完整15×25M选LR1e-5、λ.05。63项全部通过19项pilot选择复算、实际执行政策一致性及model/data/bank/config/core SHA审计，按410M、1B、2.8B顺序追加同一master队尾；A/B优先顺序保留。机器读入口results/extended_formal_freeze.json，各phase独立active_registry与input_snapshot，原prepared registry及50M候选不覆盖。CPU协调器只完成校准，不直接启动formal；本次正式冻结由工程审计后按既有授权执行。

只读核验使用scripts/audit_extended_runs.py：运行中加--allow-incomplete并输出独立preflight文件；全部63项完成后以--compare-weights --equivalence-proof-output results/extended_final_model_equivalence_proofs.json执行最终审计。它按各自100M/25M horizon验证每step floor预算、同seed流与LR、153step验证及val-only best、K/唯一覆盖/重复暴露与嵌套教师成本；不读取test或行为评分。完整model_state证明只在63项全部passed时发布，带各checkpoint文件SHA与原model_fingerprint算法SHA，可供后续评分去重D/B4 final；best未经独立证明不复用。33项辅助CPU回归日志为logs/tests_extended_auxiliary_freeze.log。
